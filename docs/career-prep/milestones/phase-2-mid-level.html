Phase 2: Mid-Level Complexity (Sprints 13-24)

Back to Master Dashboard

info

Phase Goal

Master non-linear data structures (Graphs, Heaps), introduce Dynamic Programming, apply clean Object-Oriented Design (SOLID & LLD), and learn non-relational storage (NoSQL) alongside fundamental System Design patterns.

Stage 4: Graph Algorithms & NoSQL Architecture​

Sprint 13: Graph BFS/DFS & In-Memory Caching​

Track A: DSA & Object-Oriented Principles​

  • Problem: Number of Islands (Matrix DFS/BFS)
  • Problem: Clone Graph
  • Theory: Adjacency List vs Adjacency Matrix representation

Track B: Systems & NoSQL​

  • In-Memory Storage: Redis architecture, single-threaded event loop, and data structures (Strings, Hashes, Lists, Sets, Sorted Sets)
  • Caching Basics: Cache eviction algorithms (LRU, LFU, FIFO)
  • Capacity Math: Calculating RAM footprint for in-memory caches

Sprint 14: Directed Acyclic Graphs & Document Databases​

Track A: DSA & Object-Oriented Principles​

  • Problem: Course Schedule (Topological Sort / Cycle Detection in Directed Graphs)
  • Problem: Course Schedule II (Kahn's Algorithm using indegrees)
  • Theory: OOP Foundations (Encapsulation, Abstraction, Polymorphism, Inheritance vs Composition)

Track B: Systems & NoSQL​

  • Document Stores: MongoDB internal architecture, WiredTiger storage engine, and BSON
  • Data Modeling: Embedding vs Referencing documents
  • Trade-offs: Document stores vs traditional relational tables

Sprint 15: Disjoint Set & Distributed Key-Value Stores​

Track A: DSA & Object-Oriented Principles​

  • Problem: Redundant Connection (Disjoint Set / Union-Find with Path Compression)
  • Problem: Number of Connected Components in an Undirected Graph
  • Theory: The SOLID Principles (Single Responsibility and Open/Closed deep dive)

Track B: Systems & NoSQL​

  • Distributed Key-Value: Amazon DynamoDB architecture (Partition keys, Sort keys)
  • Indexes: Global Secondary Indexes (GSI) vs Local Secondary Indexes (LSI)
  • Consistency: Strongly Consistent Reads vs Eventually Consistent Reads

Sprint 16: Wide-Column Stores & Domain Technical Alignment​

Track A: DSA & Object-Oriented Principles​

  • Problem: Graph Valid Tree
  • Theory: SOLID Principles (Liskov Substitution, Interface Segregation, Dependency Inversion)
  • Practice: Identify SOLID violations in standard Spring/React code snippets

Track B: Systems & Domain Alignment​

  • Wide-Column: Apache Cassandra storage model (SSTables, Memtables, CommitLog, Compaction)
  • Domain Mapping: Connect past technical architectural choices to measurable business KPIs
  • Case Study: When to choose Cassandra vs DynamoDB vs PostgreSQL

Stage 5: Priority Queues, Trees & System Components​

Sprint 17: Heaps & Caching Patterns​

Track A: DSA & Design Patterns​

  • Problem: Kth Largest Element in an Array (Min-Heap approach)
  • Problem: Top K Frequent Elements
  • Design Patterns: Creational Patterns (Factory, Abstract Factory, Builder, Singleton)

Track B: System Design Components​

  • Caching Strategies: Cache-Aside vs Read-Through vs Write-Through vs Write-Back
  • Cache Pitfalls: Cache Stampede / Thundering Herd, Cache Penetration, Cache Avalanche
  • Invalidation: TTL vs Event-Driven Cache Invalidation strategies

Sprint 18: Tries & Content Delivery Networks​

Track A: DSA & Design Patterns​

  • Problem: Implement Trie (Prefix Tree)
  • Problem: Design Add and Search Words Data Structure
  • Design Patterns: Structural Patterns (Adapter, Decorator, Facade, Proxy)

Track B: System Design Components​

  • Content Delivery Networks (CDN): Edge caching, Points of Presence (PoP), Anycast routing
  • CDN Optimization: Static asset caching, Cache-Control headers, Stale-While-Revalidate
  • Domain Study: Standard frontend and backend architectures in target industry verticals

Sprint 19: Backtracking & Load Balancing​

Track A: DSA & Design Patterns​

  • Problem: Subsets (Backtracking template)
  • Problem: Permutations
  • Design Patterns: Behavioral Patterns (Strategy, Observer, Command, Template Method)

Track B: System Design Components​

  • Load Balancing: Layer 4 (Transport) vs Layer 7 (Application) Load Balancers
  • Balancing Algorithms: Round Robin, Least Connections, Weighted Response Time
  • Routing: Consistent Hashing and its role in distributed caches and load balancing

Sprint 20: Concurrency Primitives & First System Design​

Track A: DSA & Concurrency​

  • Problem: Combination Sum
  • Java Concurrency: synchronized keyword, intrinsic locks, and the volatile modifier
  • Practice: Implement a thread-safe Singleton using double-checked locking

Track B: System Design Problem 1​

  • HLD Problem: Design a URL Shortener (e.g., TinyURL / Bitly)
  • Focus: Functional vs non-functional requirements, API definition, Base62 encoding vs MD5
  • Design: Capacity estimation for 100M daily active users and DB schema design

Stage 6: Dynamic Programming & Low-Level Design​

Sprint 21: 1D Dynamic Programming & System Design Problem 2​

Track A: DSA & LLD​

  • Problem: Climbing Stairs
  • Problem: House Robber
  • DP Process: Define State, Transition equation, Base cases, and Space optimization

Track B: System Design Problem 2​

  • HLD Problem: Design a Pastebin or Distributed File Storage Service
  • Focus: Metadata storage vs Blob storage (e.g., S3), presigned URLs, read/write quotas
  • Architecture: Flow diagram from client to object storage with CDN integration

Sprint 22: LLD Case Studies & System Design Problem 3​

Track A: Low-Level Design (LLD)​

  • LLD Problem: Design a Parking Lot System
  • Implementation: Class diagrams, entities, strategy pattern for pricing, and concurrency safety
  • Code: Write idiomatic, clean Java code demonstrating SOLID and clean boundaries

Track B: System Design Problem 3​

  • HLD Problem: Design an API Rate Limiter
  • Algorithms: Token Bucket, Leaky Bucket, Fixed Window Counter, Sliding Window Log
  • Distributed Rate Limiting: Redis Lua scripts for atomic increment and race condition avoidance

Sprint 23: M.Tech Synergy & Mathematical Capacity Estimation​

Track A: Advanced Algorithms & LLD​

  • LLD Problem: Design an Elevator Management System
  • M.Tech Synergy: Review formal algorithmic complexity, amortized analysis, and mathematical proofs
  • Problem: Coin Change (Unbounded Knapsack / DP)

Track B: System Design Math Mastery​

  • Capacity Math: Master the numbers every systems engineer should know (L1 cache vs RAM vs SSD vs Disk vs Network roundtrip)
  • Conversion Drills: Converting daily active users to QPS, read/write ratios, and storage growth per year
  • Trade-off Analysis: High availability vs strict consistency trade-offs

Sprint 24: Phase 2 Consolidation & Buffer​

Track A: Review & Self-Assessment​

  • Time-Boxed Practice: 2 medium DSA problems (1 Graph, 1 DP) under 45 minutes
  • LLD Review: Review class diagrams and pattern implementations for Parking Lot and Elevator
  • Buffer: Catch up on any missed topics from Sprints 13-23

Track B: Review & Self-Assessment​

  • System Design Review: Present URL Shortener or Rate Limiter aloud using Mermaid.js diagrams
  • Notes Sync: Ensure all design patterns and NoSQL architectures are documented in system-design/
  • Retrospective: Evaluate study velocity and adjust plan for Q3
