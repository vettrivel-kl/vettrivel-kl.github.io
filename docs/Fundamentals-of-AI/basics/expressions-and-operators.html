Expressions and Operators

Topic — An expression is any valid combination of values, variables, and operators that Python evaluates to produce a result. While arithmetic symbols look familiar from primary school mathematics, Python's runtime introduces critical computational nuances: division (/) always returns a float, floor division (//) rounds toward negative infinity, and exponentiation (**) evaluates right-to-left. This guide details operator mechanics, order of operations, and five ways to structure the same calculation.

1. The Core Concept​

Python divides arithmetic into seven core operations:

*Multiplication10 * 660intProduct / repeated scaling

//Floor Division23 // 54intRounds toward negative infinity

tip

If you only take one thing from this page

In Python 3, single slash / is True Division and always returns a float (10 / 2 evaluates to 5.0, not 5). Double slash // is Floor Division and rounds down toward −∞-\infty−∞. Exponentiation ** evaluates right-to-left (2 ** 3 ** 2 == 512, not 646464).

3. Order of Precedence (PEMDAS Hierarchy)​

When an expression contains multiple operators, Python resolves them according to a strict binding hierarchy:

1 (Highest)Parentheses( )Innermost first
2Exponentiation**Right-to-Left
3Unary signs+x, -x, ~xRight-to-Left
4Multiplicative*, /, //, %Left-to-Right
5Additive+, -Left-to-Right

info

The Exponentiation Associativity Exception

Every binary arithmetic operator (+, -, *, /, //, %) is left-associative (a−b−ca - b - ca−b−c is evaluated as (a−b)−c(a - b) - c(a−b)−c).

The only exception is ** (Exponentiation), which is right-associative:

232=2(32)=29=5122^{3^2} = 2^{(3^2)} = 2^9 = 512232=2(32)=29=512

If you intend (23)2=82=64(2^3)^2 = 8^2 = 64(23)2=82=64, you must explicitly add parentheses: (2 ** 3) ** 2.

4. Five Ways to Structure the Same Calculation​

Consider calculating the average of three exam scores (85,90,9285, 90, 9285,90,92):

  • 1. Direct Inline Expression
  • 2. Intermediate Variables
  • 3. Collection Aggregation
  • 4. Reusable Function
  • 5. Structured Class

# Parentheses strictly required to prevent / from dividing only 92!
average = (85 + 90 + 92) / 3
print(f"Average: {average:.2f}")  # 89.00
  • Pros: Compact one-liner.
  • Cons: Hardcoded values; not reusable.

score1, score2, score3 = 85, 90, 92
total = score1 + score2 + score3
count = 3
average = total / count
print(f"Average: {average:.2f}")
  • Pros: Self-documenting; easier to debug and step through.

scores = [85, 90, 92]
average = sum(scores) / len(scores)
print(f"Average: {average:.2f}")
  • Pros: Scales automatically to any number of scores without changing code.

def calculate_average(values: list[float]) -> float:
    if not values:
        return 0.0
    return sum(values) / len(values)

print(calculate_average([85, 90, 92]))
  • Pros: Encapsulates business logic with zero-division guardrails.

from dataclasses import dataclass

@dataclass
class StudentRecord:
    name: str
    scores: list[float]

    @property
    def average(self) -> float:
        return sum(self.scores) / len(self.scores) if self.scores else 0.0

student = StudentRecord("Vettri", [85, 90, 92])
print(f"{student.name}: {student.average:.2f}")
  • Pros: Production enterprise architecture binding data to behaviors.

6. Common Mistakes​

  • 1. Ignoring Precedence in Divisions
  • 2. Assuming // Truncates Toward Zero
  • 3. Misreading Modulo % as Percentage
  • 4. Assuming ** is Left-Associative
  • 5. Implicit String and Integer Addition

  • The Misconception: "Writing a + b + c / 3 computes the average of three numbers."
  • Wrong Thinking: Assuming addition happens left-to-right before division.
  • The Right Principle: Division / has higher precedence than addition. Python evaluates a + b + (c / 3). You must wrap the sum in parentheses: (a + b + c) / 3.

  • The Misconception: "Floor division // just chops off the decimal part."
  • Wrong Thinking: Expecting -10 // 3 to equal -3.
  • The Right Principle: // rounds down toward negative infinity (⌊x⌋\lfloor x \rfloor⌊x⌋). Since −10/3=−3.333-10 / 3 = -3.333−10/3=−3.333, rounding down yields -4. To truncate toward zero, use int(-10 / 3).

  • The Misconception: "Calling 25 % 4 gives 25% of 4 (1.0)."
  • Wrong Thinking: Confusing the mathematical modulo operator with percentage calculation.
  • The Right Principle: % returns the integer remainder after division (25=4×6+1  ⟹  125 = 4 \times 6 + 1 \implies 125=4×6+1⟹1). To compute percentages, multiply the ratio by 100: (num / total) * 100.

  • The Misconception: "2 ** 3 ** 2 evaluates as (2 ** 3) ** 2 = 64."
  • Wrong Thinking: Reading chained powers left to right.
  • The Right Principle: ** is right-associative: 2(32)=29=5122^{(3^2)} = 2^9 = 5122(32)=29=512. Use explicit parentheses if you desire left-to-right evaluation.

  • The Misconception: "'5' + 5 will evaluate to '55' or 10."
  • Wrong Thinking: Expecting JavaScript-style type coercion.
  • The Right Principle: Python is strictly typed. Adding string and integer raises TypeError: can only concatenate str (not "int") to str. Cast explicitly: int('5') + 5   ⟹  10\implies 10⟹10 or '5' + str(5)   ⟹  ′55′\implies '55'⟹′55′.

7. Summary​

Operator Mechanics

  • True Division (/): Always produces float (10/2 == 5.0).
  • Floor Division (//): Rounds toward −∞-\infty−∞ (-23//5 == -5).
  • Modulo (%): Remainder; matches sign of divisor.
  • Exponentiation (**): Right-to-left associativity (2**3**2 == 512).

Precedence Best Practices

  • PEMDAS: (), **, unary, * / // %, + -, comparisons, not, and, or.
  • Parentheses are Free: Use parentheses whenever precedence is not immediately obvious to human readers.
  • String Overloading: + concatenates strings; * repeats sequences.
  • Pairing // and %: Splitting quantities into units and leftovers (mins // 60 and mins % 60).

info

Key Takeaways

  • Division is always float: In Python 3, single slash / will never return an int.
  • Negative floor rounds down: Remember that // floors toward −∞-\infty−∞, meaning -10 // 3 == -4.
  • Right-to-left power: Exponentiation ** evaluates right-to-left; always add parentheses if in doubt.

Review Flashcards​

1. [THEORY] Why does Python evaluate -10 // 3 as -4 rather than -3?

  • Floor Function Definition: In mathematics and Python, floor division is defined by the mathematical floor operator: ⌊x⌋=max⁡{m∈Z∣m≤x}\lfloor x \rfloor = \max \{ m \in \mathbb{Z} \mid m \le x \}⌊x⌋=max{m∈Z∣m≤x}
  • Exact quotient: −10/3=−3.3333…-10 / 3 = -3.3333\dots−10/3=−3.3333…
  • The largest integer less than or equal to −3.3333…-3.3333\dots−3.3333… is -4.
  • Many languages (C/Java) truncate toward zero (yielding -3), but Python strictly floors toward negative infinity.
2. [MATH] What is the exact output of print(2 + 3 * 4 ** 2 - 6 / 3)? Trace step by step.

  1. Exponentiation: 42=164^2 = 1642=16. Expression becomes: 2+3×16−6/32 + 3 \times 16 - 6 / 32+3×16−6/3.
  2. Multiplication & Division:
    • 3×16=483 \times 16 = 483×16=48
    • 6/3=2.06 / 3 = 2.06/3=2.0 (Division produces float!)
    • Expression becomes: 2+48−2.02 + 48 - 2.02+48−2.0.
  3. Addition & Subtraction (Left-to-Right):
    • 2+48=502 + 48 = 502+48=50
    • 50−2.0=48.050 - 2.0 = \mathbf{48.0}50−2.0=48.0 (Float due to division operand).
3. [PRACTICE] How do you convert 127 minutes into hours and remaining minutes in two lines of code?

total_minutes = 127
hours = total_minutes // 60      # 2 hours (whole units)
minutes = total_minutes % 60     # 7 minutes (remainder)
print(f"{hours}h {minutes}m")    # 2h 7m
  • Alternatively, use Python's built-in divmod:
hours, minutes = divmod(127, 60) # (2, 7)
4. [ANALYZE] What happens when evaluating 5 > 3 and 2 > 4 or not False? Trace precedence.

  1. Relational Comparisons:
    • 5 > 3   ⟹  True\implies \text{True}⟹True
    • 2 > 4   ⟹  False\implies \text{False}⟹False
    • Expression: True and False or not False.
  2. Boolean not: not False   ⟹  True\implies \text{True}⟹True.
    • Expression: True and False or True.
  3. Boolean and: True and False   ⟹  False\implies \text{False}⟹False.
    • Expression: False or True.
  4. Boolean or: False or True   ⟹  True\implies \mathbf{\text{True}}⟹True.
5. [THEORY] What is the difference between = (assignment), == (equality), and is (identity)?

  • = Assignment: Binds a variable name to an object on the heap (x = [1, 2]).
  • == Equality: Checks whether two objects hold the same values/contents ([1, 2] == [1, 2] is True).
  • is Identity: Checks whether two variables reference the exact same object at the same memory address ([1, 2] is [1, 2] is False).
