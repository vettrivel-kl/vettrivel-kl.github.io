# Input and Output

> **Topic —** Interactive Python applications communicate with the outside world through standard input and output streams (`sys.stdin` and `sys.stdout`). While `input()` and `print()` appear deceptively simple, two fundamental rules govern their behavior: **`input()` strictly returns a string** (even if the user types digits), and **`print()` provides `sep` and `end` parameters** to customize delimiters and line terminations. This guide details stream mechanics, safe casting, and multi-value input parsing.

---

## 1. The Core Concept

In Python, command-line I/O operates via two built-in functions:

1.  **`input(prompt)` (Reading Input):** Pauses program execution, displays an optional prompt message on the terminal, waits for the user to press Enter, and returns the entered line.
    *   **The Cardinal Rule:** `input()` **ALWAYS returns a `str`**.
2.  **`print(*objects, sep=' ', end='\n')` (Writing Output):** Converts any number of positional arguments to text, inserts `sep` between them, appends `end` to the line, and flushes to the terminal screen.

:::tip

**If you only take one thing from this page**

`input()` **never** returns a number. If a user types `25`, Python stores the string `"25"`. To perform mathematical arithmetic, you must explicitly cast: `age = int(input("Enter age: "))`.

:::

## 4. Comparing Print Syntax Options

Printing variables and text together in Python can be written in three distinct styles:

<Tabs>
  <TabItem value="fstring" label="1. F-Strings — Standard Best Practice" default>
    <br/>
    
    ```python
    student = "Vettri"
    marks = 95
    print(f"Student: {student} | Marks: {marks}")
    ```
    *   **Pros:** Cleanest, fastest, most readable; values sit exactly where they appear.
    *   **Cons:** Python 3.6+ only.
  </TabItem>
  <TabItem value="commas" label="2. Comma Separation (*objects)">
    <br/>
    
    ```python
    student = "Vettri"
    marks = 95
    print("Student:", student, "| Marks:", marks)
    ```
    *   **Pros:** Converts non-strings automatically; no manual `str()` needed.
    *   **Cons:** Automatically injects spaces between every argument.
  </TabItem>
  <TabItem value="concat" label="3. String Concatenation (+)">
    <br/>
    
    ```python
    student = "Vettri"
    marks = 95
    # Must explicitly wrap numbers with str()!
    print("Student: " + student + " | Marks: " + str(marks))
    ```
    *   **Pros:** Works in all legacy Python versions.
    *   **Cons:** Forgetting `str()` raises `TypeError`; tedious and unreadable.
  </TabItem>
</Tabs>

## 6. Common Mistakes

<Tabs>
  <TabItem value="m1" label="🚨 1. Arithmetic on Raw input()" default>
    <br/>
    
    *   **The Misconception:** *"If the user enters 25, calling `age + 5` equals 30."*
    *   **❌ Wrong Thinking:** Forgetting that `input()` returns a string.
    *   **✅ The Right Principle:** `"25" + 5` raises `TypeError: can only concatenate str to str`. You must wrap the input call: `age = int(input())`.
  </TabItem>
  <TabItem value="m2" label="🚨 2. int(input()) on Decimals">
    <br/>
    
    *   **The Misconception:** *"int(input()) can parse numbers with decimals like '25.5'."*
    *   **❌ Wrong Thinking:** Expecting `int()` to parse decimal points.
    *   **✅ The Right Principle:** `int("25.5")` crashes with `ValueError`. If input can contain decimals, parse through `float(input())` first.
  </TabItem>
  <TabItem value="m3" label="🚨 3. Concatenating Numbers with +">
    <br/>
    
    *   **The Misconception:** *"Writing `print("Age: " + 30)` works like in JavaScript."*
    *   **❌ Wrong Thinking:** Relying on implicit type coercion.
    *   **✅ The Right Principle:** Python never converts integers to strings implicitly. Use commas `print("Age:", 30)` or f-strings `print(f"Age: {30}")`.
  </TabItem>
  <TabItem value="m4" label="🚨 4. Expecting sep Between Separate print() Calls">
    <br/>
    
    *   **The Misconception:** *"Setting `sep=','` in one print statement separates it from the next print statement."*
    *   **❌ Wrong Thinking:** Believing `sep` applies across lines.
    *   **✅ The Right Principle:** `sep` only controls characters placed *between arguments within a single call*. To control how a call ends, customize `end`.
  </TabItem>
  <TabItem value="m5" label="🚨 5. Missing Bare print() After Loop">
    <br/>
    
    *   **The Misconception:** *"Printing loop elements with `end=' '` terminates automatically."*
    *   **❌ Wrong Thinking:** Leaving the terminal cursor hanging on the same line.
    *   **✅ The Right Principle:** The next `print()` in your program will run directly onto the end of the loop output. Add a bare `print()` immediately after the loop to flush a newline.
  </TabItem>
</Tabs>

  <summary>❓ <b>3. [THEORY] What is the difference between `print("Age: " + str(30))` and `print("Age:", 30)`?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   `print("Age: " + str(30))` performs string concatenation in memory first, requiring explicit `str()` casting, and passes a single combined string to `print()`.
    *   `print("Age:", 30)` passes two separate positional arguments. `print()` converts non-strings automatically and inserts the default space delimiter (`sep=' '`).
  </div>

<details>
  <summary>❓ <b>4. [PRACTICE] Why is a bare `print()` required after a loop using `print(i, end=" ")`?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   Setting `end=" "` overrides the default newline terminator `\n`.
    *   At the end of the loop, the console cursor remains sitting on the same line after the last printed item.
    *   A bare `print()` outputs the default `end='\n'`, cleanly moving the cursor to the beginning of the next line.
  </div>
</details>

<details>
  <summary>❓ <b>5. [ANALYZE] Why does `int(input())` crash if the user enters `25.0`? How do you make it resilient?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Integer Parser Strictness:** `int()` cannot parse decimal points from strings; it expects pure base-10 digits.
    *   **The Resilient Fix:** Route through `float` first:
        ```python
        val = int(float(input("Enter number: ")))
        ```
    *   This parses `"25.0"` into float `25.0`, and then truncates it into integer `25`.
  </div>
</details>
