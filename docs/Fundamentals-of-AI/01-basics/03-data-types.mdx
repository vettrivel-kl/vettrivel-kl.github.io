# Data Types

> **Topic —** Python organizes data into **four scalar types** (holding atomic values: `int`, `float`, `str`, `bool`) and **four collection types** (holding multiple elements: `list`, `tuple`, `dict`, `set`). Understanding the structural properties of each—specifically **mutability**, **ordering**, **subscript indexing**, and **hashability**—is essential for designing reliable software and efficient data pipelines.

---

## 1. The Core Concept

Every built-in Python data type is governed by three fundamental design questions:
1.  **Is it Scalar or Collection?** Does it represent a single atomic value (`int`) or a container of elements (`list`)?
2.  **Is it Mutable or Immutable?** Can the object be modified in-place at its existing memory address, or does modification allocate a new object?
3.  **Is it Ordered or Unordered?** Do elements maintain deterministic sequence positions accessible by index (`[0]`), or are they hashed sets?

### The 8 Foundational Types Overview

| Category | Type | Literal Example | Mutability | Ordering | Access Method |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Scalar** | `int` | `28` | Immutable | — | Direct scalar |
| **Scalar** | `float` | `15.75` | Immutable | — | Direct scalar |
| **Scalar** | `str` | `"Vettri"` | Immutable | Ordered | By Index (`s[0]`) |
| **Scalar** | `bool` | `True` | Immutable | — | Logical flag |
| **Collection** | `list` | `[1, 2, 3]` | **Mutable** | Ordered | By Index (`l[0]`) |
| **Collection** | `tuple` | `(1, 2, 3)` | Immutable | Ordered | By Index (`t[0]`) |
| **Collection** | `dict` | `{"id": 101}` | **Mutable** | Ordered (Keys unique) | By Key (`d["id"]`) |
| **Collection** | `set` | `{1, 2, 3}` | **Mutable** | **Unordered** | Membership only (`in`) |

:::tip

**If you only take one thing from this page**

*   Use **`list`** when you need an ordered sequence that will change.
*   Use **`tuple`** when you need an ordered record that must remain protected and hashable.
*   Use **`dict`** for lightning-fast key-value lookups.
*   Use **`set`** for unique collections and mathematical set operations (union, intersection).

:::

## 4. The Four Collection Types in Detail

<Tabs>
  <TabItem value="list" label="1. list — [1, 2, 3]" default>
    <br/>
    
    *   **Syntax:** Square brackets `[]`.
    *   **Properties:** Ordered sequence, supports mixed types, allows duplicates, mutable.
    *   **Indexing & Slicing:**
        ```python
        nums = [10, 20, 30, 40]
        nums[0]      # 10 (First)
        nums[-1]     # 40 (Last)
        nums[1:3]    # [20, 30] (Stop index excluded)
        ```
    *   **Common Methods:** `.append(x)`, `.insert(i, x)`, `.pop()`, `.remove(x)`.
  </TabItem>
  <TabItem value="tuple" label="2. tuple — (1, 2, 3)">
    <br/>
    
    *   **Syntax:** Parentheses `()`.
    *   **Trailing Comma Rule:** `(42,)` is a 1-element tuple. `(42)` is an integer!
    *   **Properties:** Ordered sequence, immutable, hashable (can be a dict key).
    *   **Why use tuple?** Faster access, smaller memory footprint, protects data from accidental modification.
  </TabItem>
  <TabItem value="dict" label="3. dict — {'a': 1}">
    <br/>
    
    *   **Syntax:** Key-value pairs inside curly braces `{key: value}`.
    *   **Properties:** Fast $\mathcal{O}(1)$ average lookup by key, mutable, preserves insertion order (since Python 3.7).
    *   **Safe Retrieval:**
        ```python
        user = {"name": "Alex", "age": 28}
        user["salary"]              # KeyError!
        user.get("salary", 50000)   # Returns 50000 (safe default)
        ```
  </TabItem>
  <TabItem value="set" label="4. set — {1, 2, 3}">
    <br/>
    
    *   **Syntax:** Unique elements inside curly braces `{1, 2, 3}` or `set()`.
    *   **Empty Set Trap:** `{}` creates an empty **`dict`**, not a set! To make an empty set, you must call `set()`.
    *   **Properties:** Unordered (no indexing `s[0]`), duplicates automatically stripped, elements must be hashable.
    *   **Mathematical Set Operations:**
        ```python
        A = {1, 2, 3}
        B = {3, 4, 5}
        A | B    # {1, 2, 3, 4, 5} (Union)
        A & B    # {3}             (Intersection)
        A - B    # {1, 2}          (Difference)
        A ^ B    # {1, 2, 4, 5}    (Symmetric Difference)
        ```
  </TabItem>
</Tabs>

## 6. Common Mistakes

<Tabs>
  <TabItem value="m1" label="1. Single-Element Tuple Comma" default>
    <br/>
    
    *   **The Misconception:** *"Parentheses alone create a tuple, so `x = (42)` is a single-element tuple."*
    *   **Wrong Thinking:** Typing `x = (42)`.
    *   **The Right Principle:** Parentheses are also used for arithmetic grouping. Without a trailing comma, `(42)` is evaluated as integer `42`. You must write `x = (42,)`.
  </TabItem>
  <TabItem value="m2" label="2. The Empty Set Trap">
    <br/>
    
    *   **The Misconception:** *"To create an empty set, type `s = {}`."*
    *   **Wrong Thinking:** `type({})` is `<class 'dict'>`.
    *   **The Right Principle:** `{}` was reserved for dictionaries historically. Calling `type({})` returns `dict`. To create an empty set, call the constructor: `s = set()`.
  </TabItem>
  <TabItem value="m3" label="3. Attempting to Index a Set">
    <br/>
    
    *   **The Misconception:** *"I can access the first element of a set using `my_set[0]`."*
    *   **Wrong Thinking:** Treating sets like lists.
    *   **The Right Principle:** Sets are unordered hash tables without sequence indices. `my_set[0]` raises `TypeError: 'set' object is not subscriptable`. Use `for item in my_set:` or convert via `list(my_set)[0]`.
  </TabItem>
  <TabItem value="m4" label="4. Using Mutable Objects as Dict Keys">
    <br/>
    
    *   **The Misconception:** *"I can use a list as a key in a dictionary to look up coordinates."*
    *   **Wrong Thinking:** `d[[10, 20]] = "Home"`.
    *   **The Right Principle:** Dictionary keys must be hashable. Lists are mutable and unhashable, raising `TypeError: unhashable type: 'list'`. Use an immutable tuple instead: `d[(10, 20)] = "Home"`.
  </TabItem>
  <TabItem value="m5" label="5. Sets Absorbing Booleans">
    <br/>
    
    *   **The Misconception:** *"A set containing `1` and `True` will have length 2."*
    *   **Wrong Thinking:** Expecting type distinction in sets for `1` and `True`.
    *   **The Right Principle:** Because `bool` inherits from `int`, `True == 1` and `hash(True) == hash(1)`. The set treats them as duplicates and retains only one: `len({1, True}) == 1`.
  </TabItem>
</Tabs>

**Key Takeaways**

*   **Mutability dictates safety:** Lists and dicts can be modified in-place; tuples and strings cannot.
*   **Hashability requires immutability:** Only immutable types (integers, strings, tuples) can be used as dictionary keys or set elements.
*   **Shallow immutability:** A tuple containing a mutable list can have its inner list modified in-place.

### Review Flashcards

<details>
  <summary><b>1. [THEORY] Why can't a list be used as a key in a Python dictionary?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **The Hashability Invariant:** Python dictionaries are hash tables. When a key is inserted, Python computes its hash integer: `hash(key)`.
    *   If a key could be mutated in-place (e.g. `key.append(5)`), its hash integer would change, making the entry impossible to find in its original hash bucket.
    *   To prevent silent data corruption, Python enforces that all dictionary keys must be **immutable and hashable**. Passing a list raises `TypeError: unhashable type: 'list'`.
  </div>
</details>

<details>
  <summary><b>2. [MATH] Why does `len({1, True, 1.0})` evaluate to 1 instead of 3?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Value Equality and Matching Hashes:** In Python:
        $$1 == \text{True} == 1.0$$
        $$\text{hash}(1) == \text{hash}(\text{True}) == \text{hash}(1.0) == 1$$
    *   Because sets strictly eliminate duplicate elements that share both equal value and identical hash values, `True` and `1.0` are absorbed by the integer `1`.
    *   The set contains only a single element, so its length is `1`.
  </div>
</details>

<details>
  <summary><b>3. [PRACTICE] What is the difference between `dict["key"]` and `dict.get("key")`?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   `dict["key"]` attempts direct lookup. If the key is missing, it raises an unhandled `KeyError` exception.
    *   `dict.get("key")` safely returns `None` if the key is missing.
    *   `dict.get("key", default)` allows specifying a fallback return value (e.g. `d.get("count", 0)`), preventing crashes without requiring explicit `if key in d:` checks.
  </div>
</details>

<details>
  <summary><b>4. [THEORY] Why is `x = (42)` an integer, while `x = (42,)` is a tuple?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Grammar Disambiguation:** In Python syntax, parentheses `()` serve dual roles:
        1. Expression grouping: `(2 + 3) * 4`
        2. Tuple construction: `(1, 2)`
    *   If `(42)` were parsed as a tuple, mathematical grouping would be impossible.
    *   The Python grammar specifies that **the comma `,` is what constructs a tuple**, not the parentheses! The trailing comma in `(42,)` flags it as a tuple.
  </div>
</details>

<details>
  <summary><b>5. [ANALYZE] How do you create an empty set in Python, and why does `{}` not work?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **To create an empty set:** Call the constructor function: `s = set()`.
    *   **Why `{}` fails:** Dictionaries were introduced in Python long before sets were added. Curly braces `{}` were already reserved to create an empty dictionary (`type({}) == dict`).
    *   Writing `{}` creates an empty dictionary, not an empty set.
  </div>
</details>
