# Values and Types

> **Topic —** In Python, data is not stored in rigid, statically typed boxes. Instead, **every value is an object in memory that carries its own type**, and variables are merely named tags pointing to those objects. This guide explores the four foundational primitive types (`int`, `float`, `str`, `bool`), type inspection via `type()` and `isinstance()`, the boolean integer inheritance surprise, floating-point precision traps, and casting rules.

---

## 1. The Core Concept

In programming, we distinguish between two fundamental concepts:
*   A **Value** is the concrete piece of information (e.g., `100`, `15.75`, `"Python"`, `True`).
*   A **Type** is the blueprint defining what operations are legal on that value (e.g., you can divide an `int`, slice a `str`, but cannot add an `int` to a `str`).

Python is **dynamically typed**: you never declare a variable's type. Python inspects the value at runtime and assigns the appropriate class blueprint automatically:

| Expression | Python Interpretation | Assigned Data Type | Full Type Object |
| :--- | :--- | :--- | :--- |
| `100` | Whole number without decimal | `int` | `<class 'int'>` |
| `15.75` | Real number with decimal point | `float` | `<class 'float'>` |
| `"Python"` | Characters enclosed in quotes | `str` | `<class 'str'>` |
| `True` | Logical boolean keyword | `bool` | `<class 'bool'>` |

<Heading as="h3" id="float" style={{ display: 'none' }}>Floating-Point Numbers (float)</Heading>

:::tip

**If you only take one thing from this page**

In Python, **variables do not have types; values have types**. A variable is simply a name tag attached to an object in memory. If you reassign `x = 100` and then `x = "Python"`, the variable `x` has simply moved its pointer from an integer object to a string object.

:::

## 3. Three Ways to Query Types in Python

<Tabs>
  <TabItem value="isinstance" label="1. isinstance(x, T) — Standard Best Practice" default>
    <br/>
    
    *   **Syntax:** `isinstance(value, target_type)`
    *   **Returns:** `True` or `False`.
    *   **Why it's preferred:** Correctly accounts for class inheritance. Also accepts a tuple of types:
        ```python
        # Checks if x is either an integer or floating-point number
        if isinstance(x, (int, float)):
            print("x is numeric")
        ```
  </TabItem>
  <TabItem value="typeobj" label="2. type(x) — Raw Type Object">
    <br/>
    
    *   **Syntax:** `type(value)`
    *   **Returns:** The raw type object itself (`<class 'int'>`).
    *   **Trap with == comparison:**
        ```python
        type(100) == int      # True
        type(True) == int     # False! (Checks exact class, ignoring inheritance)
        ```
  </TabItem>
  <TabItem value="name" label="3. type(x).__name__ — Clean String Output">
    <br/>
    
    *   **Syntax:** `type(value).__name__`
    *   **Returns:** The class name as a clean string: `'int'`, `'float'`, `'str'`, `'bool'`.
    *   **Best For:** Human-readable display output and logging without string slicing.
  </TabItem>
</Tabs>

<Heading as="h2" id="bool-is-a-subclass-of-int">4. The Boolean Inheritance Surprise</Heading>

In Python, `bool` is a direct subclass of `int`. This historical architecture design catches many developers off guard:

```python
issubclass(bool, int)       # True
isinstance(True, int)       # True! True IS an integer!
```

### Consequences of Boolean Inheritance

```python
True == 1                   # True
False == 0                  # True
True + True                 # 2  (Arithmetic works!)
True * 50                   # 50
```

:::warning

**The If-Elif Subclass Pitfall**

Because `True` is an instance of `int`, checking `isinstance(val, int)` before `isinstance(val, bool)` will falsely intercept booleans:

```python
# ❌ BUG: True matches the int check!
if isinstance(val, int):
    print("Number")
elif isinstance(val, bool): # Never reached!
    print("Flag")

# ✅ FIX: Always check bool first
if isinstance(val, bool):
    print("Flag")
elif isinstance(val, int):
    print("Number")
```

:::

<Heading as="h2" id="type-conversion-casting">5. Type Conversion and Casting Pitfalls</Heading>

Python provides built-in constructors (`int()`, `float()`, `str()`, `bool()`) to cast between types:

<Tabs>
  <TabItem value="truncation" label="1. Truncation vs. Rounding" default>
    <br/>
    
    *   `int(15.75)` evaluates to **`15`**.
    *   **Rule:** `int()` **truncates toward zero**; it does *not* round to the nearest whole integer.
    *   To round properly according to standard arithmetic rules, use `round(15.75)` $\implies 16$.
  </TabItem>
  <TabItem value="valueerror" label="2. The Decimal String Trap">
    <br/>
    
    *   `int("100")` succeeds ($100$).
    *   `int("15.75")` **crashes with a `ValueError`**!
    *   **Why:** `int()` can only parse base-10 digit strings. It cannot parse decimal points.
    *   **Fix:** Route through `float` first: `int(float("15.75"))` $\implies 15$.
  </TabItem>
  <TabItem value="truthiness" label="3. Falsy Values in Python">
    <br/>
    
    <Heading as="h3" id="truthy-and-falsy">Truthy and Falsy Values in Python</Heading>

    In Python, **only exactly seven values convert to `False`**:
    1. `False`
    2. `0` (Integer zero)
    3. `0.0` (Float zero)
    4. `""` (Empty string)
    5. `[]` (Empty list)
    6. `{}` (Empty dict / set)
    7. `None`
    
    **Every other object is Truthy**, including strings containing `"False"` or `"0"`:
    ```python
    bool("False")  # True! (Non-empty string)
    bool("0")      # True!
    bool(-1)       # True! (Any non-zero number)
    ```
  </TabItem>
</Tabs>

## 7. Common Mistakes

<Tabs>
  <TabItem value="m1" label="🚨 1. Lowercase Booleans" default>
    <br/>
    
    *   **The Misconception:** *"In Python, booleans can be typed as `true` or `false` like in JavaScript."*
    *   **❌ Wrong Thinking:** Typing `flag = true`.
    *   **✅ The Right Principle:** Python keywords are case-sensitive. `true` raises a `NameError: name 'true' is not defined`. Always capitalize: `True` and `False`.
  </TabItem>
  <TabItem value="m2" label="🚨 2. Accidentally Quoting Numbers">
    <br/>
    
    *   **The Misconception:** *"A number is a number regardless of whether it has quotes."*
    *   **❌ Wrong Thinking:** `val = "100"` followed by arithmetic `val * 2`.
    *   **✅ The Right Principle:** Quotes create a `str`. `"100" * 2` performs sequence repetition resulting in `"100100"`. Remove quotes for mathematical numbers (`val = 100`).
  </TabItem>
  <TabItem value="m3" label="🚨 3. Forgetting input() Returns String">
    <br/>
    
    *   **The Misconception:** *"If a user types 25 into `input()`, Python stores it as an integer."*
    *   **❌ Wrong Thinking:** `age = input(); age + 5` raises `TypeError: can only concatenate str to str`.
    *   **✅ The Right Principle:** `input()` **always** returns a `str`. You must explicitly convert it: `age = int(input())`.
  </TabItem>
  <TabItem value="m4" label="🚨 4. Believing int() Rounds Numbers">
    <br/>
    
    *   **The Misconception:** *"Calling `int(15.75)` gives 16 because .75 is closer to 16."*
    *   **❌ Wrong Thinking:** Treating `int()` as a rounding function.
    *   **✅ The Right Principle:** `int()` completely discards the fractional part (truncates toward zero). To round, use `round(15.75)`.
  </TabItem>
  <TabItem value="m5" label="🚨 5. Assuming bool('False') is False">
    <br/>
    
    *   **The Misconception:** *"Converting the word 'False' to bool gives False."*
    *   **❌ Wrong Thinking:** Expecting string semantic parsing from `bool()`.
    *   **✅ The Right Principle:** In Python, `bool(s)` evaluates whether string `s` is non-empty. Because `"False"` contains 5 characters, `bool("False")` evaluates to `True`! Only `""` is `False`.
  </TabItem>
</Tabs>

<details>
  <summary>❓ <b>1. [THEORY] Why does Python evaluate `0.1 + 0.2 == 0.3` as False?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Base-2 Binary Fractions:** Computers represent floating-point numbers in binary.
    *   Just as $\frac{1}{3} = 0.3333\dots$ has an infinite repeating decimal in base-10, $0.1$ and $0.2$ are infinite repeating fractions in base-2:
        $$0.1_{10} = 0.0001100110011\dots_2$$
    *   When truncated to 53 bits of precision, $0.1 + 0.2$ yields:
        $$0.3000000000000000444\dots$$
    *   **Safe Comparison:** Never use `==` on floats. Use `math.isclose(a, b)` or `abs(a - b) < 1e-9`.
  </div>
</details>

<details>
  <summary>❓ <b>2. [THEORY] Why does `isinstance(True, int)` evaluate to True, but `type(True) == int` evaluates to False?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Inheritance:** In Python, `bool` is a subclass of `int` (`issubclass(bool, int) == True`).
    *   `isinstance(obj, Class)` checks if `obj` is an instance of `Class` **or any class derived from it**. Because `True` is a `bool` and `bool` inherits from `int`, `isinstance` returns `True`.
    *   `type(obj) == Class` checks for **exact class identity**, ignoring inheritance. Because `type(True)` is `<class 'bool'>` and not `<class 'int'>`, it evaluates to `False`.
  </div>
</details>

<details>
  <summary>❓ <b>3. [PRACTICE] Why does `int("15.75")` raise a ValueError, and how do you fix it?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Base-10 Parsing Limit:** The `int(s)` constructor expects a string consisting purely of integer digits. The character `.` is not a valid base-10 digit, so Python raises `ValueError: invalid literal for int() with base 10: '15.75'`.
    *   **The Fix:** Parse the decimal string through `float()` first, then truncate to integer:
        ```python
        int(float("15.75"))  # Evaluates to 15
        ```
  </div>
</details>

<details>
  <summary>❓ <b>4. [ANALYZE] What is printed by `print(bool("False"))` and `print(bool(""))`?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   `print(bool("False"))` prints **`True`**.
    *   `print(bool(""))` prints **`False`**.
    *   **The Principle:** In Python, string truthiness is determined strictly by sequence length (`len(s) > 0`). It does not parse the semantic English meaning of the letters inside the string. Only an empty string `""` has length 0 and evaluates to `False`.
  </div>
</details>

<details>
  <summary>❓ <b>5. [THEORY] What does it mean that Python is dynamically typed?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Types Belong to Objects, Not Variables:** In statically typed languages (like C or Java), a variable is declared with a fixed type (`int x = 10;`) and can never hold any other type.
    *   In Python, variables are simply pointers (labels) in the namespace. An object on the heap carries its type header.
    *   Reassigning `x = 10` to `x = "hello"` merely rebinds the label `x` to a different object in memory; Python handles this without compiler errors.
  </div>
</details>
