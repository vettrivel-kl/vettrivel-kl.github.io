# F-Strings

> **Topic —** Introduced in Python 3.6, **formatted string literals (`f"..."`)** are the standard, modern mechanism for string interpolation. They replace cumbersome `%` formatting and verbose `.format()` calls with an expressive, high-performance syntax evaluated directly at runtime. This guide covers expression embedding, numeric formatting (precision, commas, percentages), field alignment and padding, and self-documenting debug expressions (`f"{x=}"`).

---

## 1. The Core Concept

An f-string is created by prefixing any string literal with `f` or `F`. Expressions placed inside curly braces `{}` are evaluated at runtime and converted into string representations:

```python
name = "Alice"
age = 25
print(f"My name is {name} and I am {age} years old.")
# Output: My name is Alice and I am 25 years old.
```

The `f` prefix is **mandatory**. Omitting it prevents interpolation, printing the braces literally:

```python
print(f"Hello {name}")    # Output: Hello Alice   (Interpolated)
print("Hello {name}")     # Output: Hello {name}  (Literal text)
```

:::tip

**If you only take one thing from this page**

F-strings are **expressions evaluated at runtime**, not static templates. You can place any valid Python expression inside `{}`: mathematical arithmetic, method calls (`{name.upper()}`), dictionary indexing (`{user['id']}`), ternary conditions, or function calls.

:::

## 3. Comparison with Legacy Formatting Methods

Python evolved through four distinct string formatting paradigms. F-strings dominate in readability, conciseness, and runtime execution speed:

```python
name = "Bob"
age = 30

# 1. String Concatenation (Python 1) - Verbose, requires manual str()
msg1 = "My name is " + name + " and I am " + str(age) + " years old."

# 2. % Formatting (Python 2 / printf) - Fragile type specifiers
msg2 = "My name is %s and I am %d years old." % (name, age)

# 3. str.format() (Python 2.7 / 3.0) - Disconnected positional indexes
msg3 = "My name is {} and I am {} years old.".format(name, age)

# 4. F-Strings (Python 3.6+) - Modern, in-place, direct evaluation
msg4 = f"My name is {name} and I am {age} years old."
```

| Method | Introduced | Syntax Clarity | Performance | Main Limitation |
| :--- | :--- | :--- | :--- | :--- |
| **Concatenation (`+`)** | Python 1.0 | Poor | Slow | Explicit `str()` conversion required on numbers |
| **`%` Formatting** | Python 2.0 | Moderate | Moderate | Manual tuple packing; runtime type mismatches |
| **`str.format()`** | Python 2.7 | Good | Moderate | Arguments detached from string insertion points |
| **F-Strings (`f"..."`)** | **Python 3.6** | **Superior** | **Fastest** | Standard industrial baseline |

## 4. Format Specifier Mini-Language Reference

The expression inside curly braces follows this canonical grammar sequence:

```text
{value !conversion : fill align sign # 0 width , .precision type}
```

<Tabs>
  <TabItem value="numbers" label="1. Numeric Specifiers" default>
    <br/>
    
    *   **`.2f` (Fixed-point decimals):** `f"{19.999:.2f}"` $\implies$ `'20.00'` (Rounds to 2 decimals).
    *   **`,` (Thousands separator):** `f"{1234567:,}"` $\implies$ `'1,234,567'`.
    *   **`.1%` (Percentage):** `f"{0.8567:.1%}"` $\implies$ `'85.7%'` (Multiplies by 100 and adds `%`).
    *   **`.2e` (Scientific notation):** `f"{1234567:.2e}"` $\implies$ `'1.23e+06'`.
    *   **`+` (Explicit Sign):** `f"{42:+}"` $\implies$ `'+42'`.
  </TabItem>
  <TabItem value="alignment" label="2. Alignment and Padding">
    <br/>
    
    *   **`<` (Left align):** `f"{'hi':<6}"` $\implies$ `'hi    '`.
    *   **`>` (Right align):** `f"{'hi':>6}"` $\implies$ `'    hi'`.
    *   **`^` (Center align):** `f"{'hi':^6}"` $\implies$ `'  hi  '`.
    *   **Fill Character:** Goes immediately before the alignment token:
        ```python
        f"{'Python':*^14}"   # '****Python****'
        f"{42:05d}"          # '00042' (Zero-padded integer)
        ```
  </TabItem>
  <TabItem value="dynamic" label="3. Dynamic Widths">
    <br/>
    
    Nested braces allow column widths to be parameterized dynamically at runtime:
    ```python
    col_width = 15
    f"{'Name':<{col_width}} | {'Score':>{col_width}}"
    ```
  </TabItem>
</Tabs>

## 7. Common Mistakes

<Tabs>
  <TabItem value="m1" label="1. Forgetting the 'f' Prefix" default>
    <br/>
    
    *   **The Misconception:** *"Typing `"{name}"` will automatically insert the variable."*
    *   **Wrong Thinking:** Forgetting the leading `f`.
    *   **The Right Principle:** Without the leading `f`, Python treats `{name}` as literal text characters. You must write `f"{name}"`.
  </TabItem>
  <TabItem value="m2" label="2. Aligning Booleans Directly">
    <br/>
    
    *   **The Misconception:** *"Writing `f'{True:<10}'` aligns the word 'True'."*
    *   **Wrong Thinking:** Applying a numeric width specifier to a boolean.
    *   **The Right Principle:** Because `bool` inherits from `int`, Python formats `True` as integer `1`. Always convert to string first: `f"{str(True):<10}"`.
  </TabItem>
  <TabItem value="m3" label="3. Expecting .2f to Truncate">
    <br/>
    
    *   **The Misconception:** *"Specifying `.2f` chops off decimals after 2 places."*
    *   **Wrong Thinking:** Expecting truncation on `19.999`.
    *   **The Right Principle:** `.2f` performs standard arithmetic **rounding** (`19.999` rounds up to `20.00`). If true truncation is needed, truncate mathematically via `int(x * 100) / 100`.
  </TabItem>
  <TabItem value="m4" label="4. Literal Braces in F-Strings">
    <br/>
    
    *   **The Misconception:** *"Writing `f'{Hello}'` prints literal curly braces."*
    *   **Wrong Thinking:** Forgetting to double curly braces.
    *   **The Right Principle:** Python attempts to evaluate `Hello` as a variable name and raises a `NameError`. To print a literal brace, double it: `f"{{Hello}}"`.
  </TabItem>
  <TabItem value="m5" label="5. Backslashes Inside Braces (Python <= 3.11)">
    <br/>
    
    *   **The Misconception:** *"I can write `f'{'\\n'.join(items)}'` directly inside the braces."*
    *   **Wrong Thinking:** Using escape characters inside expressions in Python $\le$ 3.11.
    *   **The Right Principle:** In Python 3.11 and earlier, backslashes inside `{}` raise a `SyntaxError`. Pre-compute the joined string into a variable outside the f-string first.
  </TabItem>
</Tabs>

*   **Double braces to escape:** Always use `{{` and `}}` when generating JSON or literal braces.

### Review Flashcards

<details>
  <summary><b>1. [THEORY] Why do f-strings execute significantly faster than `str.format()` and `%` formatting?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Compile-Time Parsing:** When Python compiles an f-string into bytecode, it parses the string literal into separate constant strings and expression evaluation opcodes (e.g., `FORMAT_VALUE`, `BUILD_STRING`).
    *   In contrast, `str.format()` and `%` formatting must parse and re-interpret the template string at **runtime** on every single function call.
    *   F-strings avoid this runtime parsing overhead, executing at native C-level speed.
  </div>
</details>

<details>
  <summary><b>2. [PRACTICE] How do you format a float `ratio = 0.8567` as a percentage rounded to 1 decimal place?</b></summary>
  <div className="answer-content">
    <br/>
    
    ```python
    ratio = 0.8567
    print(f"{ratio:.1%}")  # Output: '85.7%'
    ```
    *   The `%` specifier automatically multiplies the floating-point value by 100, rounds to the specified decimal precision (`.1`), and appends the `%` symbol.
  </div>
</details>

<details>
  <summary><b>3. [THEORY] What does the `=` specifier do in Python 3.8+ f-strings?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Self-Documenting Debugging:** Adding an equals sign `=` immediately after the expression tells Python to print the literal expression text followed by `=` and its evaluated result:
        ```python
        score = 95
        print(f"{score=}")        # Output: 'score=95'
        print(f"{score * 2=}")    # Output: 'score * 2=190'
        ```
    *   This eliminates the redundant boilerplate of writing `print("score =", score)`.
  </div>
</details>

<details>
  <summary><b>4. [PRACTICE] How do you construct a centered 16-character string padded with asterisks `*`?</b></summary>
  <div className="answer-content">
    <br/>
    
    ```python
    title = "Python"
    print(f"{title:*^16}")  # Output: '*****Python*****'
    ```
    *   `*` represents the fill character.
    *   `^` specifies center alignment.
    *   `16` sets the total field width.
  </div>
</details>

<details>
  <summary><b>5. [ANALYZE] How do you escape literal curly braces in an f-string when generating JSON?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Double Curly Braces:** In an f-string, `{{` renders as a literal `{`, and `}}` renders as a literal `}`:
        ```python
        user_id = 101
        payload = f'{{"user_id": {user_id}}}'
        print(payload)  # Output: '{"user_id": 101}'
        ```
    *   The outer double braces escape the JSON syntax, while the inner single brace evaluates the Python variable `user_id`.
  </div>
</details>
