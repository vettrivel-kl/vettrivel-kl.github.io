# Applications and Major Techniques

> **Topic —** Across all of artificial intelligence, machine learning performs about **nine core techniques**. Every industry application is either one of these nine or a combination of them. The essential skill of an ML engineer is **translating a business question into its corresponding technique** by inspecting the shape of the required output.

---

## 1. The Nine Techniques at a Glance

The fastest way to identify the correct technique is to examine **what shape the answer is**:

| # | Technique | Core Question | Output Shape | Canonical Scikit-Learn Class | Example Application |
|---|---|---|---|---|---|
| 1 | **Regression** | *How much? How many?* | Continuous number ($\mathbb{R}$) | `LinearRegression`, `Ridge` | Predicting house prices, demand forecasting |
| 2 | **Classification** | *Which category?* | Discrete class label | `LogisticRegression`, `RandomForest` | Churn prediction, spam detection, medical triage |
| 3 | **Clustering** | *What natural groups exist?* | Cluster ID per row | `KMeans`, `DBSCAN` | Customer segmentation, document grouping |
| 4 | **Association** | *What co-occurs?* | "If A, then B" rules | `apriori` (mlxtend) | Market basket analysis (frequently bought together) |
| 5 | **Anomaly Detection** | *What doesn't belong?* | Binary inlier/outlier flag | `IsolationForest`, `OneClassSVM` | Credit-card fraud, equipment sensor failure |
| 6 | **Sequence Mining** | *What comes next?* | Next item in ordered chain | `MarkovModel`, `LSTM`, `RNN` | Clickstream tracking, predictive search queries |
| 7 | **Dimensionality Reduction** | *Can I compress these columns?* | Lower-dimensional projection | `PCA`, `TSNE`, `UMAP` | Visualizing 100 features in 2D, noise reduction |
| 8 | **Recommendation** | *What else would this user like?* | Ranked list per user | Collaborative Filtering, SVD | Netflix movie recommendations, Spotify playlists |
| 9 | **Generative AI** | *Can we generate new assets?* | Novel text, audio, image | Transformers, Diffusion | Large Language Models (LLMs), image synthesis |

:::tip

**The Two-Question Decision Shortcut**

1.  **Do you have historical answers (labels)?**
    *   **Yes:** You are in Supervised Learning (Regression, Classification, or Sequence Mining).
    *   **No:** You are in Unsupervised Learning (Clustering, Association, Anomaly Detection, or PCA).
2.  **If labeled, is the answer a continuous number or a discrete name?**
    *   **Continuous number:** $\implies$ **Regression** (where numeric proximity matters).
    *   **Discrete name / category:** $\implies$ **Classification** (where labels are distinct categories).

:::

## 4. Key Distinctions & Boundary Traps

<Tabs>
  <TabItem value="clf_reg" label="1. Classification vs. Regression" default>
    <br/>
    
    *   **The Trap:** *"Our loan default model outputs `0.83`, so it's regression."*
    *   **The Principle:** In loan prediction, `0.83` is the model's posterior confidence probability $P(\text{Default} \mid X)$. The underlying ground truth is discrete ($\{0, 1\}$).
    *   **The Litmus Test:** Does numeric proximity matter? If predicting $52$ for $50$ is partly right, it is **Regression**. If predicting Class B for Class A is completely wrong, it is **Classification**.
  </TabItem>
  <TabItem value="assoc_reco" label="2. Association vs. Recommendation">
    <br/>
    
    *   **Association:** Operates on **items** (Market Basket Analysis: *"If a basket contains diapers, it contains beer with 60% confidence"*). The shopper's identity is completely ignored.
    *   **Recommendation:** Operates on **people** (Collaborative Filtering: *"Because user Alex watched Interstellar and has similar watch histories to user Jordan, recommend Inception"*).
  </TabItem>
  <TabItem value="anom_clf" label="3. Anomaly Detection vs. Classification">
    <br/>
    
    *   **When to use Classification:** When you possess balanced, confirmed labels for both normal and fraudulent events ($>1\%$ frequency).
    *   **When to use Anomaly Detection:** When fraudulent events are unlabelled, extremely rare ($<0.1\%$), or when future attacks look nothing like past attacks.
  </TabItem>
</Tabs>

## 6. Common Mistakes

<Tabs>
  <TabItem value="m1" label="🚨 1. Confusing Output Format with Task Type" default>
    <br/>
    
    *   **The Misconception:** *"A probability output like 0.85 means the algorithm is performing regression."*
    *   **❌ Wrong Thinking:** Judging a model by its mathematical floating-point format.
    *   **✅ The Right Principle:** Check the **ground-truth target**. If the target in your training table is a discrete class (`defaulted` vs `paid`), the task is **Classification**.
  </TabItem>
  <TabItem value="m2" label="🚨 2. Labeling Datasets Instead of Questions">
    <br/>
    
    *   **The Misconception:** *"This customer dataset is a classification dataset."*
    *   **❌ Wrong Thinking:** Believing a dataset is locked to a single technique.
    *   **✅ The Right Principle:** Datasets are neutral containers. You can run Regression on `monthly_spend`, Classification on `churned`, and Clustering on unlabeled demographic features. The business question picks the technique.
  </TabItem>
  <TabItem value="m3" label="🚨 3. Assuming Shuffling Never Matters">
    <br/>
    
    *   **The Misconception:** *"Shuffling dataset rows has no impact on model training."*
    *   **❌ Wrong Thinking:** Treating all data as independent and identically distributed (i.i.d.).
    *   **✅ The Right Principle:** In **Sequence Mining** and time-series forecasting, temporal order carries the informational signal. Shuffling rows completely destroys the transition dynamics.
  </TabItem>
  <TabItem value="m4" label="🚨 4. Association vs. Personalized Recommendations">
    <br/>
    
    *   **The Misconception:** *"Market basket analysis gives personalized product suggestions to users."*
    *   **❌ Wrong Thinking:** Confusing co-occurrence with individual taste profiling.
    *   **✅ The Right Principle:** Association rules are global to the checkout basket (*"If coffee, then sugar"*). True recommendation systems require user interaction history to personalize suggestions.
  </TabItem>
</Tabs>

**📌 Key Takeaways**

*   **🎯 Output Shape Dictates Technique:** Always identify the technique by what the answer looks like (continuous number, discrete label, cluster ID, or ranked list).
*   **🛠️ Data Does Not Pick the Technique:** A single customer dataset can simultaneously support regression, classification, clustering, anomaly detection, and PCA.
*   **⚠️ The 0.83 Probability Trap:** Output probabilities express confidence in classification; they do not turn the problem into regression.

<details>
  <summary>❓ <b>1. [THEORY] How do you distinguish between Association Rules and Recommendation Systems?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Association:** Learns global co-occurrence rules between **items** (*"If coffee in basket, then sugar with 70% confidence"*). The specific individual shopper is ignored.
    *   **Recommendation Systems:** Builds personalized ranked lists tailored to **people** based on their unique individual history and taste similarity to other users.
  </div>
</details>

<details>
  <summary>❓ <b>2. [ANALYZE] Why did KMeans clustering identify the churned customers without ever seeing the `churned` labels?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Natural Behavioral Separation:** The input features (`tenure_months` and `support_tickets`) had natural mathematical boundaries.
    *   The churned customers had short tenure ($<6$ months) and high support calls ($>4$ tickets).
    *   Because their feature vectors formed an isolated cluster in coordinate space, KMeans grouped them together purely from geometric proximity without needing a label!
  </div>
</details>

<details>
  <summary>❓ <b>3. [THEORY] Which machine learning technique becomes impossible if you shuffle the order of your dataset rows? Why?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Sequence Mining:** (and time-series forecasting).
    *   **Why:** In sequence mining, the temporal order of events carries the primary informational signal (e.g. click $A \to$ click $B \to$ purchase). Shuffling rows breaks the transition probabilities, making sequential modeling impossible.
  </div>
</details>

<details>
  <summary>❓ <b>4. [PRACTICE] In our customer lab, linear regression scored $R^2 = 0.651$ while Isolation Forest flagged exactly two rows. Explain the connection.</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **One technique's noise is another technique's answer:** The linear regression model was dragged off its fit line by the two extreme spenders ($6$mo/\$95 and $36$mo/\$140), depressing $R^2$.
    *   The exact same extreme spenders were identified by Isolation Forest as statistical outliers. Removing them would restore the linear regression $R^2$ to $>0.90$.
  </div>
</details>

<details>
  <summary>❓ <b>5. [THEORY] What does PCA mean when it reports that PC1 captures 75.0% and PC2 captures 22.9% of variance? What was sacrificed?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Preserved Variance:** The first two principal components together retain $75.0\% + 22.9\% = \mathbf{97.9\%}$ of the original 3-dimensional data variance.
    *   **Sacrificed:** We discarded $2.1\%$ of information (noise/minor variation) and sacrificed direct human interpretability, as PC1 and PC2 are abstract linear combinations of the original column names.
  </div>
</details>
