What is Machine Learning?

Topic — Every subsequent algorithm in machine learning is a specialized technique. This page establishes the foundational argument for why those techniques exist: there is an entire class of real-world problems that traditional, deterministic programming fundamentally cannot solve.

1. The Core Concept​

In 1959, Arthur Samuel defined machine learning with five load-bearing words:

"Machine learning is the field of study that gives computers the ability to learn without being explicitly programmed."

  • Arthur Samuel, 1959

In 1997, computer scientist Tom Mitchell formalized this into an operational engineering framework:

"A computer program is said to learn from experience EEE with respect to some class of tasks TTT and performance measure PPP, if its performance at tasks in TTT, as measured by PPP, improves with experience EEE."

  • Tom Mitchell, 1997

If you cannot identify TTT, EEE, and PPP for a business problem, it is not a machine learning problem yet.

3. The Collapse of Explicit Programming​

In traditional programming, a human developer dictates explicit conditional instructions for every possible branch:

def calculate(a, b, op):
    if op == "+": return a + b
    if op == "-": return a - b
    if op == "*": return a * b
    if op == "/": return a / b

This works cleanly because:

  1. The mathematical rules were completely known before writing the code.
  2. The input cases are finite and countable (only 4 operations).
  3. A human can state each rule precisely in a single line.

However, consider distinguishing between cats and dogs from photos.

The Rule-Based Failure​

If you attempt to write explicit if-else rules based on physical features:

def what_animal(has_wings, num_legs, weight_kg):
    if has_wings:
        return "bird"
    if num_legs == 4 and weight_kg < 10:   # Human intuition: "small = cat"
        return "cat"
    if num_legs == 4 and weight_kg >= 10:  # Human intuition: "large = dog"
        return "dog"
    return "unknown"

This explicit system breaks immediately for three compounding reasons:

  1. Combinatorial Explosion: Each additional feature multiplies the required rule combinations exponentially (kdk^dkd).
  2. Sample-Dependent Thresholds: The 10 kg threshold is an arbitrary human guess. The moment a Chihuahua (2.5 kg2.5\text{ kg}2.5 kg, dog) or Maine Coon (12 kg12\text{ kg}12 kg, cat) arrives, the rules produce complete misclassifications.
  3. Zero Generalization: Real-world distributions drift continuously. In traditional programming, every new outlier becomes a fresh bug report requiring endless manual rule patching.

5. The Paradigm Inversion​

Machine learning resolves the combinatorial collapse by inverting the inputs and outputs of software:

The Cat-and-Dog Verification​

When a Decision Tree was trained on real animal data with 5 features (has_wings, legs, weight, snout, retractable_claws), it completely ignored weight:

Model Output

|   |--- has_wings <= 0.50
|   |   |--- class: dog
|   |--- has_wings >  0.50
|   |   |--- class: bird
|--- retractable_claws >  0.50
|   |--- class: cat

The algorithm autonomously discovered that retractable_claws cleanly separates cats from dogs with 100%100\%100% accuracy, completely avoiding the human's fragile weight threshold error on Chihuahuas and Maine Coons.

6. AI vs. ML vs. DL Taxonomy​

The terms AI, Machine Learning, and Deep Learning are not interchangeable; they form a strictly nested taxonomy:

🤖 Artificial Intelligence (Broadest Umbrella)

Any computational system exhibiting autonomous, goal-directed behavior without direct real-time human intervention (includes classical search heuristics, minimax game trees, and rule-based expert systems).

📊 Machine Learning (Statistical Subset)

Systems that learn decision boundaries and continuous functions directly from empirical data (EEE) using statistical algorithms (e.g. Linear Models, Decision Trees, SVMs, Random Forests).

🧠 Deep Learning (Hierarchical Representation Subset)

Multi-layered neural architectures (Transformers, CNNs, Diffusion models) that automatically extract raw hierarchical representations from unstructured data (audio, raw pixels, natural language tokens).

8. Common Mistakes​

  • 🚨 1. Does ML Write Programming Code?
  • 🚨 2. Using ML When Rules Are Known
  • 🚨 3. More Features Always Equals Better Models
  • 🚨 4. Confusing AI with Statistical Learning

  • The Misconception: "Machine Learning means the computer writes Python code to solve the problem."
  • ❌ Wrong Thinking: Expecting a model to generate .py files or readable procedural scripts.
  • ✅ The Right Principle: The model fits numeric weight parameters and matrix operations inside a fixed mathematical architecture chosen by the engineer.

  • The Misconception: "ML is newer and more advanced, so we should build our tax calculator and password validator with ML."
  • ❌ Wrong Thinking: Introducing statistical probabilities to problems governed by exact, countable, static laws.
  • ✅ The Right Principle: If the rules are 100% known and countable, write standard code. ML introduces stochastic error and should only be used when rules are impossible to write manually.

  • The Misconception: "Adding 50 more columns to our dataset will always improve predictive accuracy."
  • ❌ Wrong Thinking: Dumping uncleaned, collinear features into a model.
  • ✅ The Right Principle: Features multiply the dimension of the space exponentially (kdk^dkd), causing the curse of dimensionality and severe overfitting unless balanced by exponential sample size (EEE).

  • The Misconception: "If a system does not use neural networks or statistical training, it cannot be called AI."
  • ❌ Wrong Thinking: Restricting AI to learning systems only.
  • ✅ The Right Principle: AI encompasses all autonomous software. A classical chess program using Minimax search trees and hardcoded heuristics is genuine AI, even though it contains zero machine learning.

9. Summary​

🤖 Foundational Definitions

  • Arthur Samuel (1959): Learning without being explicitly programmed.
  • Tom Mitchell (1997): Performance at task TTT, measured by metric PPP, improves with experience EEE.
  • The Inversion: In ML, rules are the output, not the input.

🛠️ Why Explicit Rules Collapsed

  • Combinatorial Explosion: Rule count scales as kdk^dkd, easily outpacing human coding ability.
  • Fragile Thresholds: Hand-coded boundaries fail on unseen edge cases (Chihuahuas, Maine Coons).
  • Drift and Maintenance: Real-world data shifts continuously, rendering static rules obsolete.

info

📌 Key Takeaways

  • 🔄 The Inversion: Traditional programming runs on hand-written rules; Machine Learning generates mathematical rules and weights autonomously from data.
  • 🎯 Mitchell's Trinity: Always define Task (TTT), Experience (EEE), and Performance (PPP) before beginning any ML project.
  • 📦 Nested Hierarchy: DL⊂ML⊂AIDL \subset ML \subset AIDL⊂ML⊂AI. Deep learning learns features hierarchically; machine learning fits statistical boundaries; AI includes all autonomous systems.

Review Flashcards​

❓ 1. [THEORY] Mitchell's definition identifies T, E, and P. Formulate these three for an automated credit card fraud detector.

  • Task (TTT): Classify individual incoming credit card transactions in real time as legitimate or fraudulent (000 or 111).
  • Experience (EEE): A historical database of credit card transactions containing transaction amounts, merchant IDs, geo-locations, cardholder purchase frequency, and verified fraud chargebacks.
  • Performance Measure (PPP): Precision-Recall AUC (PR-AUC) or Recall at a fixed low False Positive Rate (e.g. capturing 95%95\%95% of fraud while flagging less than 0.1%0.1\%0.1% of legitimate transactions).
❓ 2. [MATH] Why does adding a 7th feature to a dataset with 3 values per feature cause a combinatorial explosion for rule-based systems?

  • With 666 features taking 333 states, the required state-space of rules is: 36=729 combinations3^6 = 729 \text{ combinations}36=729 combinations
  • Adding a 7th feature multiplies the entire state space by 333: 37=2,187 combinations3^7 = 2,187 \text{ combinations}37=2,187 combinations
  • While human developer rule-writing capacity scales linearly (O(d)O(d)O(d)), the required rule combinations scale exponentially (O(kd)O(k^d)O(kd)).
❓ 3. [THEORY] Why is a rule-based expert system or Minimax chess engine considered AI, even if it contains no Machine Learning?

  • Artificial Intelligence is the broad encompassing category of any computing system that performs autonomous, goal-directed tasks without direct human intervention.
  • A Minimax search engine autonomously evaluates chess positions and chooses optimal strategic moves. It exhibits autonomous decision-making without learning from data (EEE), satisfying the definition of AI.
❓ 4. [PRACTICE] Why did the Decision Tree in our lab ignore body weight and choose retractable_claws instead?

  • Human Cognitive Bias: Humans pick obvious continuous attributes like weight_kg based on intuition ("dogs are heavy, cats are light").
  • Covariance and Invariance: The decision tree evaluates the mathematical information gain of every feature across all training samples. It discovered that while heavy cats (Maine Coons) and light dogs (Chihuahuas) violate weight boundaries, retractable_claws provided an invariant biological separator (100%100\%100% pure split).
❓ 5. [ANALYZE] Name two software applications where Machine Learning should NEVER be used, and explain why.

  1. Salary & Tax Calculations: Tax laws and mathematical addition are exact, static, and deterministic. Using a statistical model introduces probabilistic approximation errors to a problem requiring 100%100\%100% precision.
  2. Cryptographic Password Verification: Passwords require exact byte-level matching. An ML model would predict a probability of a match, introducing false positives that compromise security.
