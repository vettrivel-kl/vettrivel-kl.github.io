# Overfitting, Underfitting, and Regularization

> **Topic —** A machine learning model fits training data with 100% precision, yet fails catastrophically on unseen customer transactions: **overfitting**. Another model is so mathematically rigid that it misses real signals entirely: **underfitting**. Regularization introduces a mathematical constraint into the loss function to penalize excessive complexity. This guide explores the **bias-variance tradeoff**, contrasts **L1 (Lasso)**, **L2 (Ridge)**, and **Elastic Net** penalties, and details geometric constraint boundaries.

---

## 1. The Core Concept

The fundamental objective of supervised learning is not resubstitution memorization, but **out-of-sample generalization**:

$$\mathbb{E}_{(x, y) \sim \mathcal{D}}\left[ \mathcal{L}(y, \hat{f}(x)) \right]$$

Every machine learning model balances two competing sources of error captured by the **Bias-Variance Decomposition**:

$$\text{Total Expected Error} = \text{Bias}[\hat{f}(x)]^2 + \text{Var}[\hat{f}(x)] + \sigma^2$$

1.  **Bias (Underfitting):** Error resulting from oversimplified mathematical assumptions. A linear model fitting quadratic data cannot capture true curvature.
2.  **Variance (Overfitting):** Error resulting from hypersensitivity to random fluctuations in the training set. A high-degree polynomial bends to pass through every noise point.
3.  **Irreducible Error ($\sigma^2$):** Intrinsic noise in the data collection process that no algorithm can eliminate.

:::tip

**If you only take one thing from this page**

**Overfitting** means your model has low bias but high variance (memorizing noise). **Underfitting** means your model has high bias but low variance (too rigid). **Regularization** adds a penalty term $\lambda \cdot \Omega(w)$ to shrink weights toward zero, trading a tiny increase in training bias for a massive reduction in test variance.

:::

## 3. Regularization Mechanics: L1 vs. L2 vs. Elastic Net

Regularization controls model complexity by adding a mathematical penalty to the objective function:

$$\text{Cost}(\mathbf{w}) = \text{Loss}(\mathbf{y}, \hat{\mathbf{y}}) + \lambda \cdot \Omega(\mathbf{w})$$

## 4. Comparing Regularization Architectures

<Tabs>
  <TabItem value="l2" label="1. L2 Regularization (Ridge)" default>
    <br/>
    
    *   **Penalty Term:** $\Omega(w) = \frac{1}{2} \sum_{j=1}^{d} w_j^2 = \frac{1}{2} \|\mathbf{w}\|_2^2$.
    *   **Gradient Contribution:** $\frac{\partial \Omega}{\partial w_j} = w_j$.
    *   **Shrinkage Behavior:** Weight update subtracts a fraction proportional to $w_j$:
        $$w_j \leftarrow w_j (1 - \alpha \lambda) - \alpha \frac{\partial \text{Loss}}{\partial w_j}$$
    *   **Sparsity:** **Never exactly zero**. Smoothly shrinks coefficients toward zero, preserving all features.
    *   **Geometry:** Spherical / circular constraint surface without sharp corners.
    *   **Best For:** Multicollinearity (correlated features), preserving all predictive signals.
  </TabItem>
  <TabItem value="l1" label="2. L1 Regularization (Lasso)">
    <br/>
    
    *   **Penalty Term:** $\Omega(w) = \sum_{j=1}^{d} |w_j| = \|\mathbf{w}\|_1$.
    *   **Gradient Contribution:** $\frac{\partial \Omega}{\partial w_j} = \text{sign}(w_j)$ (constant magnitude $\pm 1$).
    *   **Shrinkage Behavior:** Constant step reduction regardless of weight magnitude:
        $$w_j \leftarrow w_j - \alpha \lambda \cdot \text{sign}(w_j)$$
    *   **Sparsity:** **Drives uninformative weights to exact zero ($w_j = 0$)**. Performs automatic feature selection.
    *   **Geometry:** Diamond / $L_1$ polytope with sharp corners on the coordinate axes.
    *   **Best For:** Sparse feature selection when many features are pure noise.
  </TabItem>
  <TabItem value="enet" label="3. Elastic Net">
    <br/>
    
    *   **Penalty Term:** Convex linear combination of L1 and L2 penalties:
        $$\Omega(w) = \rho \|\mathbf{w}\|_1 + \frac{1 - \rho}{2} \|\mathbf{w}\|_2^2$$
    *   **The Grouping Effect:** When multiple features are strongly correlated, Lasso arbitrarily picks one and drops the others. Elastic Net groups them, shrinking them together while maintaining sparsity.
    *   **Best For:** High-dimensional data ($p \gg n$) with correlated predictor clusters.
  </TabItem>
</Tabs>

## 5. Geometric Intuition: Why Lasso Yields Zeros

Why does $L_1$ regularization produce exact zeros (sparsity), while $L_2$ regularization never does? 

In constrained optimization (Lagrange form), regularized regression solves:

$$\min_{\mathbf{w}} \text{Loss}(\mathbf{w}) \quad \text{subject to} \quad \Omega(\mathbf{w}) \le C$$

The optimal solution occurs at the **point of tangency** where the expanding unconstrained **Loss Contours (ellipses)** first touch the **Regularization Constraint Region**.

export const GeometricLassoSimulator = () => {
  const [mode, setMode] = React.useState('l1');
  const [angleDeg, setAngleDeg] = React.useState(32);
  const [budget, setBudget] = React.useState(1.0);

  const originX = 160;
  const originY = 160;
  const scale = 75;

  const rad = (angleDeg * Math.PI) / 180;
  const olsDist = 2.1;
  const olsW1 = olsDist * Math.cos(rad);
  const olsW2 = olsDist * Math.sin(rad);

  const olsX = originX + olsW1 * scale;
  const olsY = originY - olsW2 * scale;

  // Tangency calculation
  let tanW1 = 0;
  let tanW2 = 0;
  let isCorner = false;

  if (mode === 'l2') {
    // Ridge: tangency on circle at angle rad
    tanW1 = budget * Math.cos(rad);
    tanW2 = budget * Math.sin(rad);
    isCorner = false;
  } else {
    // Lasso: diamond has sharp corners on axes.
    // If angle < 45 deg, closest corner on diamond is (budget, 0).
    // If angle > 45 deg, closest corner is (0, budget).
    if (angleDeg <= 44) {
      tanW1 = budget;
      tanW2 = 0.0;
      isCorner = true;
    } else if (angleDeg >= 46) {
      tanW1 = 0.0;
      tanW2 = budget;
      isCorner = true;
    } else {
      tanW1 = budget * 0.5;
      tanW2 = budget * 0.5;
      isCorner = false;
    }
  }

  const tanX = originX + tanW1 * scale;
  const tanY = originY - tanW2 * scale;

  // Distance from OLS to tangent point
  const dx = tanX - olsX;
  const dy = tanY - olsY;
  const distContact = Math.sqrt(dx * dx + dy * dy);

  const diamondPoints = `${originX + budget * scale},${originY} ${originX},${originY - budget * scale} ${originX - budget * scale},${originY} ${originX},${originY + budget * scale}`;

  return (
    <div style={{ padding: '20px', border: '1px solid var(--ifm-color-emphasis-200)', borderRadius: '8px', backgroundColor: 'rgba(148, 163, 184, 0.05)', margin: '20px 0' }}>
      <h4 style={{ margin: '0 0 12px 0' }}>📐 Interactive Geometry of Sparsity Simulator</h4>
      <p style={{ margin: '0 0 14px 0', fontSize: '14px' }}>
        Rotate the unconstrained OLS optimum angle (θ) to observe how the expanding loss ellipses interact with the constraint boundary:
      </p>

      <div style={{ display: 'flex', gap: '8px', flexWrap: 'wrap', marginBottom: '16px' }}>
        <button
          onClick={() => setMode('l1')}
          style={{
            padding: '6px 14px',
            borderRadius: '4px',
            border: '1px solid #e53e3e',
            backgroundColor: mode === 'l1' ? '#e53e3e' : 'transparent',
            color: mode === 'l1' ? '#fff' : 'var(--ifm-font-color-base)',
            cursor: 'pointer',
            fontWeight: 'bold',
            fontSize: '12px',
            transition: '0.2s'
          }}
        >
          L1 Lasso (Diamond Constraint)
        </button>
        <button
          onClick={() => setMode('l2')}
          style={{
            padding: '6px 14px',
            borderRadius: '4px',
            border: '1px solid #3182ce',
            backgroundColor: mode === 'l2' ? '#3182ce' : 'transparent',
            color: mode === 'l2' ? '#fff' : 'var(--ifm-font-color-base)',
            cursor: 'pointer',
            fontWeight: 'bold',
            fontSize: '12px',
            transition: '0.2s'
          }}
        >
          L2 Ridge (Circular Constraint)
        </button>
      </div>

      <div style={{ display: 'grid', gridTemplateColumns: 'repeat(auto-fit, minmax(220px, 1fr))', gap: '14px', marginBottom: '16px' }}>
        <div>
          <div style={{ display: 'flex', justifyContent: 'space-between', fontSize: '13px', fontWeight: 'bold' }}>
            <span>Unconstrained OLS Angle (θ):</span>
            <span style={{ color: '#3182ce' }}>{angleDeg}°</span>
          </div>
          <input
            type="range"
            min="15"
            max="75"
            step="1"
            value={angleDeg}
            onChange={(e) => setAngleDeg(parseInt(e.target.value))}
            style={{ width: '100%', marginTop: '6px' }}
          />
        </div>
        <div>
          <div style={{ display: 'flex', justifyContent: 'space-between', fontSize: '13px', fontWeight: 'bold' }}>
            <span>Constraint Budget (C):</span>
            <span style={{ color: '#805ad5' }}>{budget.toFixed(1)}</span>
          </div>
          <input
            type="range"
            min="0.6"
            max="1.3"
            step="0.1"
            value={budget}
            onChange={(e) => setBudget(parseFloat(e.target.value))}
            style={{ width: '100%', marginTop: '6px' }}
          />
        </div>
      </div>

      <div style={{ display: 'grid', gridTemplateColumns: 'repeat(auto-fit, minmax(280px, 1fr))', gap: '16px', alignItems: 'center' }}>
        <div style={{ display: 'flex', justifyContent: 'center' }}>
          <svg viewBox="0 0 340 310" style={{ width: '100%', maxWidth: '340px', height: 'auto', backgroundColor: 'var(--ifm-background-surface-color)', borderRadius: '6px', border: '1px solid var(--ifm-color-emphasis-300)' }}>
            {/* Grid & Axes */}
            <line x1="20" y1={originY} x2="320" y2={originY} stroke="var(--ifm-color-emphasis-300)" strokeWidth="1.5" />
            <line x1={originX} y1="20" x2={originX} y2="290" stroke="var(--ifm-color-emphasis-300)" strokeWidth="1.5" />
            <text x="325" y={originY + 4} fontSize="11" fill="var(--ifm-color-emphasis-700)">w₁</text>
            <text x={originX} y="15" textAnchor="middle" fontSize="11" fill="var(--ifm-color-emphasis-700)">w₂</text>

            {/* Constraint Shape */}
            {mode === 'l2' ? (
              <circle
                cx={originX}
                cy={originY}
                r={budget * scale}
                fill="rgba(49, 130, 206, 0.15)"
                stroke="#3182ce"
                strokeWidth="2.5"
              />
            ) : (
              <polygon
                points={diamondPoints}
                fill="rgba(229, 62, 62, 0.15)"
                stroke="#e53e3e"
                strokeWidth="2.5"
              />
            )}

            {/* Loss Ellipses (Concentric around OLS) */}
            <ellipse
              cx={olsX}
              cy={olsY}
              rx={distContact}
              ry={distContact * 0.72}
              transform={`rotate(-25, ${olsX}, ${olsY})`}
              fill="none"
              stroke="#dd6b20"
              strokeWidth="2"
            />
            <ellipse
              cx={olsX}
              cy={olsY}
              rx={distContact * 0.65}
              ry={distContact * 0.45}
              transform={`rotate(-25, ${olsX}, ${olsY})`}
              fill="none"
              stroke="#dd6b20"
              strokeDasharray="3 3"
              strokeWidth="1"
            />

            {/* OLS Minimum Marker */}
            <circle cx={olsX} cy={olsY} r="5" fill="#d69e2e" stroke="#fff" strokeWidth="1.5" />
            <text x={olsX + 8} y={olsY - 8} fontSize="10" fontWeight="bold" fill="#d69e2e">ŵ_OLS</text>

            {/* Contact / Tangency Point */}
            <circle cx={tanX} cy={tanY} r="6" fill={isCorner ? '#e53e3e' : '#3182ce'} stroke="#fff" strokeWidth="2" />
            <line x1={tanX} y1={tanY} x2={olsX} y2={olsY} stroke="#718096" strokeDasharray="2 2" strokeWidth="1" />
          </svg>
        </div>

        <div>
          <div style={{ padding: '14px', borderRadius: '6px', backgroundColor: 'var(--ifm-background-surface-color)', border: `2px solid ${isCorner ? '#e53e3e' : '#3182ce'}`, marginBottom: '12px' }}>
            <div style={{ fontSize: '11px', color: 'var(--ifm-color-emphasis-600)', textTransform: 'uppercase', fontWeight: 'bold' }}>
              Optimal Constrained Solution (w*)
            </div>
            <div style={{ fontSize: '20px', fontWeight: 'bold', color: isCorner ? '#e53e3e' : '#3182ce', marginTop: '4px' }}>
              w₁ = {tanW1.toFixed(2)}, w₂ = {tanW2.toFixed(2)}
            </div>
            <div style={{ fontSize: '12px', marginTop: '4px', fontWeight: 'bold', color: isCorner ? '#c53030' : '#2b6cb0' }}>
              {isCorner ? '🎯 EXACT SPARSITY: One weight is zero (Corner Solution)!' : '⚖️ DENSE SOLUTION: Both weights remain non-zero.'}
            </div>
          </div>

          <div style={{ fontSize: '13px', lineHeight: '1.6', color: 'var(--ifm-color-emphasis-800)' }}>
            {mode === 'l1' ? (
              <span>
                <b>Why Lasso sets weights to zero:</b> The diamond constraint has sharp vertices sitting directly on the coordinate axes ($(C, 0)$ and $(0, C)$). Because the corners protrude furthest, the expanding loss ellipse <b>almost always makes initial contact at a sharp corner</b> across a wide range of angles ($15°$ to $75°$). Touching a corner forces the orthogonal weight to be <b>identically zero</b>.
              </span>

        </div>

## 7. Common Mistakes

<Tabs>
  <TabItem value="m1" label="🚨 1. Regularizing the Intercept (Bias)" default>
    <br/>
    
    *   **The Misconception:** *"The regularization penalty should apply to all parameters including the intercept $b$."*
    *   **❌ Wrong Thinking:** Adding $\lambda b^2$ to the cost function.
    *   **✅ The Right Principle:** The intercept represents the global base rate of the target. Penalizing $b$ shifts predictions away from the target mean. Scikit-learn models (`fit_intercept=True`) never regularize the bias term.
  </TabItem>
  <TabItem value="m2" label="🚨 2. Regularizing Without Feature Standardization">
    <br/>
    
    *   **The Misconception:** *"Regularization works identically regardless of whether features are scaled."*
    *   **❌ Wrong Thinking:** Applying L1 or L2 penalties to unstandardized features.
    *   **✅ The Right Principle:** The penalty $\sum w_j^2$ treats all weights identically. Features with large scales naturally have tiny weights, escaping penalization, while features with tiny scales are penalized unfairly. Always standardize features with `StandardScaler` inside a `Pipeline`.
  </TabItem>
  <TabItem value="m3" label="🚨 3. Confusing Alpha and C Parameters">
    <br/>
    
    *   **The Misconception:** *"Setting C=10 in Logistic Regression means strong regularization."*
    *   **❌ Wrong Thinking:** Inverting the meaning of $C$ and $\alpha$.
    *   **✅ The Right Principle:** In linear models (`Ridge`, `Lasso`), `alpha` ($\lambda$) represents penalty strength (large $\alpha$ = strong regularization). In `LogisticRegression` and `SVC`, `C` is the inverse penalty ($C = \frac{1}{\lambda}$). Large $C$ means weak regularization!
  </TabItem>
  <TabItem value="m4" label="🚨 4. Believing L2 Performs Feature Selection">
    <br/>
    
    *   **The Misconception:** *"Ridge regression sets unimportant features to zero if alpha is large enough."*
    *   **❌ Wrong Thinking:** Expecting L2 to produce sparse models.
    *   **✅ The Right Principle:** Because the L2 gradient $\lambda w$ diminishes as $w \to 0$, L2 coefficients asymptotically approach zero but never reach it. Only L1 (Lasso) produces exact zeros.
  </TabItem>
  <TabItem value="m5" label="🚨 5. Assuming Zero Training Error Implies Perfection">
    <br/>
    
    *   **The Misconception:** *"Our model achieved 100% training accuracy, so the algorithm is optimal."*
    *   **❌ Wrong Thinking:** Evaluating model quality using resubstitution accuracy.
    *   **✅ The Right Principle:** Zero training error is the cardinal diagnostic signature of severe overfitting. True model quality is determined strictly by out-of-sample cross-validation error.
  </TabItem>
</Tabs>

**📌 Key Takeaways**

*   **🛡️ Regularization controls variance:** Without regularization, complex models memorize sample noise rather than population signal.
*   **💎 Corners create sparsity:** The diamond geometry of L1 forces loss contours to touch on coordinate axes, performing automated feature selection.
*   **🔄 Alpha vs C inversion:** Never forget that in scikit-learn, `alpha` increases regularization, while `C` decreases regularization.

### Review Flashcards

<details>
  <summary>❓ <b>1. [THEORY] Why does L1 regularization produce sparse models (exact zeros) while L2 regularization does not?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **The Gradient Perspective:**
        *   L2 penalty is $\frac{1}{2} \lambda w^2$. Its gradient is $\lambda w$. As $w \to 0$, the gradient diminishes proportionally to zero, shrinking weights slower and slower without reaching zero.
        *   L1 penalty is $\lambda |w|$. Its subgradient is a constant $\pm \lambda$ regardless of magnitude. It continues pushing weights toward zero with full force until snapping to exact zero.
    *   **The Geometric Perspective:** The $L_1$ constraint region is a diamond with sharp corners on the coordinate axes. The unconstrained loss ellipses almost always touch the diamond at a corner where coordinates equal zero.
  </div>
</details>

<details>
  <summary>❓ <b>2. [MATH] In the Bias-Variance decomposition, what represents the theoretical lower bound on model error?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Irreducible Error ($\sigma^2$):**
        $$\mathbb{E}[(y - \hat{f}(x))^2] = \text{Bias}^2 + \text{Variance} + \sigma^2$$
    *   Even an omniscient Bayes-optimal model with zero bias and infinite training data (zero variance) will still suffer an expected error of $\sigma^2$.
    *   It represents unmeasured confounding variables, physical sensor limits, and intrinsic randomness.
  </div>
</details>

<details>
  <summary>❓ <b>3. [ANALYZE] When should you choose Elastic Net over standard Lasso (L1)?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Correlated Feature Groups:** When features are strongly collinear (e.g. 10 gene markers that activate together), Lasso arbitrarily selects one and zeroes out the remaining 9. Elastic Net groups them and preserves their collective signal.
    *   **High Dimensions ($p > n$):** In datasets where features exceed sample count, Lasso can select at most $n$ non-zero features before saturating. Elastic Net can select all $p$ features if necessary.
  </div>
</details>

<details>
  <summary>❓ <b>4. [PRACTICE] Why is feature scaling strictly mandatory before applying Ridge or Lasso regression?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Scale Asymmetry:** The penalty term $\sum w_j^2$ or $\sum |w_j|$ does not know what units features are measured in.
    *   If Feature 1 is Salary in rupees ($10^6$) and Feature 2 is Age in years ($10^1$), the OLS weight for Salary will naturally be tiny ($10^{-6}$), while the weight for Age will be large ($10^0$).
    *   Regularization will aggressively crush the Age weight while completely ignoring Salary! Standardizing with `StandardScaler` places all coefficients on a level playing field.
  </div>
</details>

<details>
  <summary>❓ <b>5. [THEORY] Why is the bias term (intercept b) excluded from the regularization penalty in scikit-learn?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Centering the Output:** The intercept $b$ captures the unconditional mean of the target variable $\mathbb{E}[y]$ when all standardized features are zero.
    *   Penalizing $b$ toward zero would force the prediction line down toward the origin, destroying accuracy even if the slope is perfectly learned.
    *   Regularization is designed to constrain feature interactions (slopes), not the global vertical baseline.
  </div>
</details>
