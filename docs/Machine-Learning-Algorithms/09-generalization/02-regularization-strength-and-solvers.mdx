# Regularization Strength and Solvers

> **Topic —** Regularization strength ($\alpha$, $\lambda$, or $C$) is not learned by gradient descent; it is a hyperparameter that must be tuned across logarithmic decades. If penalty strength is too weak, the model overfits; if too strong, it underfits by crushing all coefficients toward zero. Furthermore, scikit-learn optimization algorithms (solvers) have strict mathematical compatibility rules with specific penalties (e.g. $L_1$ vs. $L_2$). This guide covers tuning mechanics, the inverse relationship between $\alpha$ and $C$, solver selection rules, and warm-start path algorithms.

---

## 1. The Core Concept

In regularized linear models, the objective function balances training fit against parameter complexity:

$$\min_{\mathbf{w}} \text{Loss}(\mathbf{w}) + \alpha \cdot \Omega(\mathbf{w})$$

In regression (`Ridge`, `Lasso`), the hyperparameter is denoted **$\alpha$** (or $\lambda$). In classification (`LogisticRegression`, `LinearSVC`), the loss is scaled inversely by **$C$**:

$$\min_{\mathbf{w}} C \cdot \text{Loss}(\mathbf{w}) + \Omega(\mathbf{w})$$

Setting $C = \frac{1}{\alpha}$ makes both formulations mathematically equivalent:
*   **Large $\alpha$ (Small $C$):** Strong regularization $\implies$ tiny weights, high bias, low variance.
*   **Small $\alpha$ (Large $C$):** Weak regularization $\implies$ large unconstrained weights, low bias, high variance.

:::tip

**If you only take one thing from this page**

In `Ridge` and `Lasso`, **$\alpha$ represents penalty strength** (higher $\alpha$ = heavier shrinkage). In `LogisticRegression`, **$C$ is the inverse penalty** (higher $C$ = weaker shrinkage, approaching unregularized maximum likelihood). Always tune across logarithmic decades: $[10^{-3}, 10^{-2}, \dots, 10^3]$.

:::

## 4. Hyperparameter Search Strategies

<Tabs>
  <TabItem value="grid" label="1. Grid Search (Exhaustive)" default>
    <br/>
    
    *   **The Method:** Evaluates every Cartesian product combination in a predefined grid.
    *   **Best Grid Spacing:** Logarithmic decades: $\alpha \in [10^{-3}, 10^{-2}, 10^{-1}, 10^0, 10^1, 10^2]$.
    *   **Scikit-Learn Class:** `GridSearchCV`.
    *   **Pros:** Exhaustive and reproducible; guarantees finding the best point on the grid.
    *   **Cons:** Expensive if searching multiple hyperparameters simultaneously ($6 \times 6 \times 5 \text{ folds} = 180 \text{ fits}$).
  </TabItem>
  <TabItem value="random" label="2. Randomized Search">
    <br/>
    
    *   **The Method:** Samples hyperparameter configurations from continuous statistical distributions (e.g. `scipy.stats.loguniform(1e-4, 1e2)`).
    *   **Scikit-Learn Class:** `RandomizedSearchCV`.
    *   **The Statistical Advantage:** In high dimensions with multiple hyperparameters, Randomized Search explores more unique values per parameter within the same compute budget (Bergstra & Bengio, 2012).
  </TabItem>
  <TabItem value="coarse" label="3. Coarse-to-Fine Search">
    <br/>
    
    *   **Phase 1 (Coarse Pass):** Rapid sweep over wide decades: $[0.001, 0.1, 10.0, 1000.0]$. Identifies the optimal basin (e.g. $\alpha^* = 0.1$).
    *   **Phase 2 (Fine Pass):** Dense local sweep around the winner: $[0.02, 0.05, 0.1, 0.2, 0.5]$.
    *   **Pros:** Achieves high precision with minimal total compute.
  </TabItem>
  <TabItem value="path" label="4. Specialized Path Solvers (Free CV)">
    <br/>
    
    *   **The Method:** Specialized estimators (`RidgeCV`, `LassoCV`, `ElasticNetCV`) compute the entire regularization path analytically or via warm-starts.
    *   **RidgeCV:** Uses the closed-form Hat Matrix trick to compute **Leave-One-Out CV for 100 alphas in the time of a single fit**!
    *   **LassoCV:** Traces coordinate descent warm-starts where weights from $\alpha_k$ initialize $\alpha_{k+1}$, running $10\times$ faster than standard `GridSearchCV`.
  </TabItem>
</Tabs>

## 6. Common Mistakes

<Tabs>
  <TabItem value="m1" label="🚨 1. Confusing Alpha and C Inversion" default>
    <br/>
    
    *   **The Misconception:** *"I want heavier regularization in Logistic Regression, so I set C = 100."*
    *   **❌ Wrong Thinking:** Assuming $C$ behaves like $\alpha$.
    *   **✅ The Right Principle:** $C = \frac{1}{\alpha}$. Large $C$ ($C=100$) means **weak regularization**, allowing large weights. To apply heavy regularization in `LogisticRegression`, set $C \le 0.01$.
  </TabItem>
  <TabItem value="m2" label="🚨 2. Pairing L-BFGS with L1 Penalties">
    <br/>
    
    *   **The Misconception:** *"L-BFGS is the default solver, so it handles L1 feature selection automatically."*
    *   **❌ Wrong Thinking:** Requesting `penalty='l1'` with `solver='lbfgs'`.
    *   **✅ The Right Principle:** L-BFGS requires continuous second derivatives. The non-differentiable sharp corner of $L_1$ ($|w|$) causes an immediate `ValueError`. You must specify `solver='saga'`.
  </TabItem>
  <TabItem value="m3" label="🚨 3. Tuning Hyperparameters on the Test Set">
    <br/>
    
    *   **The Misconception:** *"We evaluated candidate alphas on the test set and picked the one with lowest test error."*
    *   **❌ Wrong Thinking:** Allowing test set feedback to select hyperparameters.
    *   **✅ The Right Principle:** Tuning against test scores causes implicit data leakage. Hyperparameter optimization must occur strictly on training folds via cross-validation; the test set is evaluated once.
  </TabItem>
  <TabItem value="m4" label="🚨 4. Setting Linear Grids Instead of Log Grids">
    <br/>
    
    *   **The Misconception:** *"Testing alphas on a linear grid [1, 2, 3, 4, 5] is sufficient."*
    *   **❌ Wrong Thinking:** Searching hyperparameters on an arithmetic scale.
    *   **✅ The Right Principle:** Regularization effects scale geometrically. The difference between $\alpha = 0.001$ and $0.01$ is massive, whereas the difference between $4.0$ and $5.0$ is tiny. Always use **logarithmic decade grids** ($10^{-3}, 10^{-2}, \dots, 10^2$).
  </TabItem>
  <TabItem value="m5" label="🚨 5. Ignoring Endpoint Saturation">
    <br/>
    
    *   **The Misconception:** *"Grid search returned alpha = 0.001 as best, so our tuning is complete."*
    *   **❌ Wrong Thinking:** Accepting an optimal parameter that sits on the extreme boundary of your search grid.
    *   **✅ The Right Principle:** If the winning parameter is an endpoint of your grid, the true optimum likely lies further in that direction. Expand the grid into smaller decades ($10^{-4}, 10^{-5}$) until the optimum sits cleanly in the interior.
  </TabItem>
</Tabs>

### Review Flashcards

<details>
  <summary>❓ <b>1. [THEORY] How does RidgeCV compute Leave-One-Out cross-validation for dozens of alphas almost instantaneously?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **The Analytic Shortcut:** For linear ridge regression, the out-of-sample residual for sample $i$ under LOO-CV can be calculated directly from the full-dataset fit:
        $$r_{i, \text{LOO}}(\alpha) = \frac{y_i - \hat{y}_i(\alpha)}{1 - h_{ii}(\alpha)}$$
        where $h_{ii}(\alpha)$ is the $i$-th diagonal element of the projection Hat Matrix:
        $$H(\alpha) = X(X^T X + \alpha I)^{-1} X^T$$
    *   By performing a single Singular Value Decomposition (SVD) of $X$, `RidgeCV` evaluates hundreds of candidate $\alpha$ values without ever re-fitting the model.
  </div>
</details>

<details>
  <summary>❓ <b>2. [MATH] A LogisticRegression model is trained with C = 0.05. What is the equivalent regularization penalty strength alpha?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Formula:** $\alpha = \frac{1}{C}$.
    *   $\alpha = \frac{1}{0.05} = 20.0$.
    *   Setting $C=0.05$ applies a heavy regularization penalty ($\alpha = 20$), forcing strong weight shrinkage.
  </div>
</details>

<details>
  <summary>❓ <b>3. [ANALYZE] Why are hyperparameter grids almost always defined on a logarithmic scale rather than an arithmetic scale?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Exponential Order-of-Magnitude Sensitivity:** The behavior of regularized loss surfaces changes across orders of magnitude.
    *   The difference between $\alpha = 0.001$ and $\alpha = 0.01$ changes weight shrinkage dramatically.
    *   Searching an arithmetic grid $[1.0, 2.0, 3.0, 4.0]$ completely misses the sub-1.0 weak regularization regime where most models find their optimal sweet spot.
  </div>
</details>

<details>
  <summary>❓ <b>4. [PRACTICE] What should you do if your GridSearchCV output reveals that the best parameter is the maximum value in your search grid?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Boundary Saturation Warning:** If your grid was $[0.01, 0.1, 1.0, 10.0]$ and `best_params_` returns $10.0$, the true global optimum has not been found.
    *   The loss curve was still improving as $\alpha$ increased.
    *   **The Action:** Expand the grid to larger decades: $[10.0, 50.0, 100.0, 500.0, 1000.0]$ until the optimal point sits comfortably inside the interior of the grid.
  </div>
</details>

<details>
  <summary>❓ <b>5. [THEORY] Why can't standard L-BFGS optimize models with an L1 (Lasso) penalty?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Non-Differentiable Point at Origin:** The $L_1$ penalty $|w|$ has a sharp 'V' shape with an undefined derivative at $w = 0$ (its subgradient is $[-1, 1]$).
    *   L-BFGS is a quasi-Newton method that approximates the inverse Hessian using smooth second-order Taylor series approximations.
    *   The discontinuous jump in the gradient at zero causes the quadratic approximation in L-BFGS to fail, leading to non-convergence. Proximal algorithms like SAGA or coordinate descent are required.
  </div>
</details>
