Confusion Matrix and Basic Metrics

Topic — In classification, a single overall accuracy figure frequently conceals catastrophic systematic failures. When data is imbalanced, a trivial model that always predicts the majority class can boast a 99% accuracy score while failing to catch a single positive case. This guide explores the foundational 2x2 Confusion Matrix, extracts the core counts (TP, TN, FP, FN), dissects the Accuracy Paradox, and establishes majority-class baseline benchmarks.

1. The Core Concept​

Every binary classification decision falls into one of four mutually exclusive outcomes formed by crossing the Actual Ground Truth with the Model Prediction:

  1. True Positive (TP): Ground truth is Positive (111); model predicts Positive (111). Correct hit.
  2. True Negative (TN): Ground truth is Negative (000); model predicts Negative (000). Correct rejection.
  3. False Positive (FP): Ground truth is Negative (000); model predicts Positive (111). Type I Error (False Alarm).
  4. False Negative (FN): Ground truth is Positive (111); model predicts Negative (000). Type II Error (Missed Detection).

These four counts form the Confusion Matrix:

Total Observations (N)=TP+TN+FP+FN\text{Total Observations } (N) = \text{TP} + \text{TN} + \text{FP} + \text{FN}Total Observations (N)=TP+TN+FP+FN

tip

If you only take one thing from this page

The diagonal elements (TP+TN\text{TP} + \text{TN}TP+TN) represent correct classifications. The off-diagonal elements (FP+FN\text{FP} + \text{FN}FP+FN) represent errors. Never evaluate a classifier using accuracy alone without first verifying the zero-rule majority baseline.

3. Dissecting the Four Quadrants​

In scikit-learn (sklearn.metrics.confusion_matrix), the default axis orientation is:

  • Rows: Actual True Class (yyy)
  • Columns: Predicted Class (y^\hat{y}y^​)
  • 1. True Positive (TP)
  • 2. True Negative (TN)
  • 3. False Positive (FP - Type I Error)
  • 4. False Negative (FN - Type II Error)

  • The Scenario: Model predicted 111; Truth is 111.
  • Real-world Example: A spam email correctly routed to the Junk folder, or a cancer patient correctly flagged for urgent oncology review.
  • Goal: Maximize TP.

  • The Scenario: Model predicted 000; Truth is 000.
  • Real-world Example: A legitimate email placed into the Inbox, or a healthy patient cleared without invasive biopsies.
  • Goal: Maximize TN.

  • The Scenario: Model predicted 111; Truth is 000.
  • The Impact: False Alarm. A critical job offer email flagged as spam, or a legitimate $50 credit card purchase declined at checkout.
  • Cost Profile: Creates friction and customer annoyance.

  • The Scenario: Model predicted 000; Truth is 111.
  • The Impact: Missed Detection. A fraudulent $5,000 wire transfer approved as legitimate, or a malignant tumor overlooked on an MRI.
  • Cost Profile: Catastrophic failure in high-stakes domains.

4. The Accuracy Paradox Deep-Dive​

Accuracy is defined as the proportion of total decisions that were correct:

Accuracy=TP+TNTP+TN+FP+FN=CorrectTotal\text{Accuracy} = \frac{\text{TP} + \text{TN}}{\text{TP} + \text{TN} + \text{FP} + \text{FN}} = \frac{\text{Correct}}{\text{Total}}Accuracy=TP+TN+FP+FNTP+TN​=TotalCorrect​

While intuitive for balanced classes, accuracy fails on imbalanced distributions:

The 99% Useless Model​

Imagine a fraud detection system with 10,000 transactions where only 50 are fraudulent (0.5% fraud rate):

  • A trivial model that predicts non-fraudulent on every transaction scores: Accuracy=0+995010000=99.5%\text{Accuracy} = \frac{0 + 9950}{10000} = 99.5\%Accuracy=100000+9950​=99.5%
  • Despite its dazzling 99.5%99.5\%99.5% accuracy score, it missed every single fraudulent transaction (Recall=0%\text{Recall} = 0\%Recall=0%).

The Zero-Rule Baseline Rule​

Before accepting any accuracy figure, always compute the Majority-Class Baseline:

Baseline Accuracy=max⁡(Actual Positives,Actual Negatives)Total\text{Baseline Accuracy} = \frac{\max(\text{Actual Positives}, \text{Actual Negatives})}{\text{Total}}Baseline Accuracy=Totalmax(Actual Positives,Actual Negatives)​

A model is only providing real diagnostic utility if its accuracy significantly outperforms this zero-effort majority baseline.

6. Common Mistakes​

  • 🚨 1. Swapping Axis Orientations
  • 🚨 2. Trusting Unanchored Accuracy
  • 🚨 3. Treating FP and FN as Equal Cost Errors
  • 🚨 4. Confusing TP Rate with Overall Accuracy
  • 🚨 5. Inverting Class Label Assignments

  • The Misconception: "True Positives are always located in the top-left corner of the confusion matrix."
  • ❌ Wrong Thinking: Assuming all software libraries use the same matrix layout.
  • ✅ The Right Principle: Scikit-learn puts Actual rows on the vertical axis and Predicted columns on the horizontal axis (ytrue,ypredy_{\text{true}}, y_{\text{pred}}ytrue​,ypred​), meaning TN\text{TN}TN is top-left and TP\text{TP}TP is bottom-right. Medical literature often swaps this orientation. Always read the axis labels first!

  • The Misconception: "Our defect detection model achieved 98.2% accuracy, proving it is production-ready."
  • ❌ Wrong Thinking: Quoting accuracy without stating the underlying class prevalence.
  • ✅ The Right Principle: If defects only occur on 1% of factory items, an accuracy of 98.2% is barely better than predicting 'no defect' for everything (99.0%99.0\%99.0% baseline). Always report accuracy alongside majority baselines and recall.

  • The Misconception: "Both False Positives and False Negatives are just 1 misclassification, so minimizing total errors is optimal."
  • ❌ Wrong Thinking: Assuming error symmetry in asymmetric business environments.
  • ✅ The Right Principle: In autonomous driving, a false alarm (braking for a plastic bag) costs a few seconds of driver annoyance. A missed detection (failing to brake for a pedestrian) is fatal. Metric selection must prioritize the more dangerous failure mode.

  • The Misconception: "Accuracy measures what percentage of positive events were caught."
  • ❌ Wrong Thinking: Conflating Accuracy with Recall (Sensitivity).
  • ✅ The Right Principle: Accuracy divides correct predictions by the total population. Recall divides correct positive hits by the actual positive population (TPTP+FN\frac{\text{TP}}{\text{TP} + \text{FN}}TP+FNTP​).

  • The Misconception: "Labeling healthy as 1 and sick as 0 changes nothing about metric calculations."
  • ❌ Wrong Thinking: Arbitrarily assigning the positive class (111).
  • ✅ The Right Principle: In statistical convention, the rare, actionable, or targeted event (fraud, disease, churn, defect) is assigned as the Positive Class (111). Inverting labels flips Precision, Recall, and Sensitivity calculations.

7. Summary​

🤖 Matrix Foundations

  • Diagonal Elements: TP\text{TP}TP and TN\text{TN}TN represent correct hits and correct rejections.
  • Type I Error (FP): False alarm. Predicted positive for an actual negative.
  • Type II Error (FN): Missed event. Predicted negative for an actual positive.
  • Accuracy Formula: TP+TNTotal\frac{\text{TP} + \text{TN}}{\text{Total}}TotalTP+TN​. Treats all error types identically.

🛠️ Practical Diagnostics

  • Accuracy Paradox: On imbalanced datasets, trivial majority guessing yields inflated accuracy with zero recall.
  • Baseline Anchor: Always compare accuracy to max⁡(P,N)Total\frac{\max(P, N)}{\text{Total}}Totalmax(P,N)​.
  • Axis Check: In scikit-learn, rows are actual true labels and columns are predictions.
  • Asymmetric Costs: Real-world applications demand tracking Precision and Recall separately.

info

📌 Key Takeaways

  • 📊 Confusion matrix is the source of truth: All classification metrics (Precision, Recall, F1, Specificity, ROC-AUC) are derived directly from these four quadrant counts.
  • ⚠️ Accuracy lies on imbalanced data: When classes are skewed, high accuracy can coincide with a totally useless model.
  • 🎯 Zero-Rule anchor: A model must show statistically significant lift above the majority class prevalence to provide real engineering value.

Review Flashcards​

❓ 1. [THEORY] How are the four quadrants of a confusion matrix mapped in scikit-learn when calling cm.ravel()?

  • In scikit-learn, binary confusion matrices are ordered by class labels [0,1][0, 1][0,1]:
    • Row 0: Actual Negatives (y=0y=0y=0)   ⟹  \implies⟹ Columns [0,1][0, 1][0,1] are TN,FP\text{TN}, \text{FP}TN,FP.
    • Row 1: Actual Positives (y=1y=1y=1)   ⟹  \implies⟹ Columns [0,1][0, 1][0,1] are FN,TP\text{FN}, \text{TP}FN,TP.
  • Calling tn, fp, fn, tp = confusion_matrix(y_true, y_pred).ravel() unpacks them in exact row-major order: Index 0→TN,Index 1→FP,Index 2→FN,Index 3→TP\text{Index } 0 \to \text{TN}, \quad \text{Index } 1 \to \text{FP}, \quad \text{Index } 2 \to \text{FN}, \quad \text{Index } 3 \to \text{TP}Index 0→TN,Index 1→FP,Index 2→FN,Index 3→TP
❓ 2. [ANALYZE] Why is a Type II error (False Negative) typically considered far more dangerous than a Type I error (False Positive) in medical diagnostics?

  • Type I Error (False Positive): A healthy patient is flagged as potentially having disease. The consequence is a follow-up test, temporary anxiety, and slight medical expense.
  • Type II Error (False Negative): A patient with an aggressive tumor is told they are healthy. The consequence is missed treatment, disease progression, and avoidable mortality.
  • Because the cost of missing a true positive is catastrophic, diagnostic models prioritize high Recall (minimizing FN\text{FN}FN) over high Precision.
❓ 3. [MATH] Given TN = 85, FP = 15, FN = 5, TP = 95, calculate Overall Accuracy and Specificity.

  • Total Observations: N=85+15+5+95=200N = 85 + 15 + 5 + 95 = 200N=85+15+5+95=200.
  • Accuracy: Accuracy=TP+TNN=95+85200=180200=0.90(90.0%)\text{Accuracy} = \frac{\text{TP} + \text{TN}}{N} = \frac{95 + 85}{200} = \frac{180}{200} = 0.90 \quad (90.0\%)Accuracy=NTP+TN​=20095+85​=200180​=0.90(90.0%)
  • Specificity (True Negative Rate): Specificity=TNActual Negatives=TNTN+FP=8585+15=85100=0.85(85.0%)\text{Specificity} = \frac{\text{TN}}{\text{Actual Negatives}} = \frac{\text{TN}}{\text{TN} + \text{FP}} = \frac{85}{85 + 15} = \frac{85}{100} = 0.85 \quad (85.0\%)Specificity=Actual NegativesTN​=TN+FPTN​=85+1585​=10085​=0.85(85.0%)
❓ 4. [PRACTICE] How do you compute the baseline accuracy of a dataset containing 850 non-churners and 150 churners?

  • Majority Class: Non-churners with 850 samples.
  • Total Samples: 850+150=1000850 + 150 = 1000850+150=1000.
  • Baseline Zero-Rule Accuracy: Baseline=8501000=0.85(85.0%)\text{Baseline} = \frac{850}{1000} = 0.85 \quad (85.0\%)Baseline=1000850​=0.85(85.0%)
  • A churn prediction model that achieves 86.0%86.0\%86.0% accuracy provides almost zero value (+1.0% lift over blind guessing).
❓ 5. [THEORY] Can accuracy ever be higher than both Precision and Recall simultaneously?

  • Yes: If a dataset has heavy negative class dominance (e.g. 90% negatives) and the model accurately classifies negatives (TN\text{TN}TN is high), while missing some positives (FN\text{FN}FN is moderate) and making a few false alarms (FP\text{FP}FP is low).
  • Accuracy will be buoyed by the large TN\text{TN}TN count, even if Precision and Recall on the rare positive class are mediocre.
