# Confusion Matrix and Basic Metrics

> **Topic —** In classification, a single overall accuracy figure frequently conceals catastrophic systematic failures. When data is imbalanced, a trivial model that always predicts the majority class can boast a 99% accuracy score while failing to catch a single positive case. This guide explores the foundational **2x2 Confusion Matrix**, extracts the core counts (**TP, TN, FP, FN**), dissects the **Accuracy Paradox**, and establishes majority-class baseline benchmarks.

---

## 1. The Core Concept

Every binary classification decision falls into one of four mutually exclusive outcomes formed by crossing the **Actual Ground Truth** with the **Model Prediction**:

1.  **True Positive (TP):** Ground truth is Positive ($1$); model predicts Positive ($1$). Correct hit.
2.  **True Negative (TN):** Ground truth is Negative ($0$); model predicts Negative ($0$). Correct rejection.
3.  **False Positive (FP):** Ground truth is Negative ($0$); model predicts Positive ($1$). **Type I Error** (False Alarm).
4.  **False Negative (FN):** Ground truth is Positive ($1$); model predicts Negative ($0$). **Type II Error** (Missed Detection).

These four counts form the **Confusion Matrix**:

$$\text{Total Observations } (N) = \text{TP} + \text{TN} + \text{FP} + \text{FN}$$

:::tip

**If you only take one thing from this page**

The diagonal elements ($\text{TP} + \text{TN}$) represent correct classifications. The off-diagonal elements ($\text{FP} + \text{FN}$) represent errors. Never evaluate a classifier using accuracy alone without first verifying the **zero-rule majority baseline**.

:::

## 3. Dissecting the Four Quadrants

In scikit-learn (`sklearn.metrics.confusion_matrix`), the default axis orientation is:
*   **Rows:** Actual True Class ($y$)
*   **Columns:** Predicted Class ($\hat{y}$)

## 4. The Accuracy Paradox Deep-Dive

**Accuracy** is defined as the proportion of total decisions that were correct:

$$\text{Accuracy} = \frac{\text{TP} + \text{TN}}{\text{TP} + \text{TN} + \text{FP} + \text{FN}} = \frac{\text{Correct}}{\text{Total}}$$

While intuitive for balanced classes, accuracy fails on imbalanced distributions:

### The 99% Useless Model

Imagine a fraud detection system with 10,000 transactions where only 50 are fraudulent (0.5% fraud rate):
*   A trivial model that **predicts non-fraudulent on every transaction** scores:
    $$\text{Accuracy} = \frac{0 + 9950}{10000} = 99.5\%$$
*   Despite its dazzling $99.5\%$ accuracy score, it missed every single fraudulent transaction ($\text{Recall} = 0\%$).

### The Zero-Rule Baseline Rule

Before accepting any accuracy figure, always compute the **Majority-Class Baseline**:

$$\text{Baseline Accuracy} = \frac{\max(\text{Actual Positives}, \text{Actual Negatives})}{\text{Total}}$$

A model is only providing real diagnostic utility if its accuracy significantly outperforms this zero-effort majority baseline.

## 6. Common Mistakes

<Tabs>
  <TabItem value="m1" label="🚨 1. Swapping Axis Orientations" default>
    <br/>
    
    *   **The Misconception:** *"True Positives are always located in the top-left corner of the confusion matrix."*
    *   **❌ Wrong Thinking:** Assuming all software libraries use the same matrix layout.
    *   **✅ The Right Principle:** Scikit-learn puts Actual rows on the vertical axis and Predicted columns on the horizontal axis ($y_{\text{true}}, y_{\text{pred}}$), meaning $\text{TN}$ is top-left and $\text{TP}$ is bottom-right. Medical literature often swaps this orientation. Always read the axis labels first!
  </TabItem>
  <TabItem value="m2" label="🚨 2. Trusting Unanchored Accuracy">
    <br/>
    
    *   **The Misconception:** *"Our defect detection model achieved 98.2% accuracy, proving it is production-ready."*
    *   **❌ Wrong Thinking:** Quoting accuracy without stating the underlying class prevalence.
    *   **✅ The Right Principle:** If defects only occur on 1% of factory items, an accuracy of 98.2% is barely better than predicting 'no defect' for everything ($99.0\%$ baseline). Always report accuracy alongside majority baselines and recall.
  </TabItem>
  <TabItem value="m3" label="🚨 3. Treating FP and FN as Equal Cost Errors">
    <br/>
    
    *   **The Misconception:** *"Both False Positives and False Negatives are just 1 misclassification, so minimizing total errors is optimal."*
    *   **❌ Wrong Thinking:** Assuming error symmetry in asymmetric business environments.
    *   **✅ The Right Principle:** In autonomous driving, a false alarm (braking for a plastic bag) costs a few seconds of driver annoyance. A missed detection (failing to brake for a pedestrian) is fatal. Metric selection must prioritize the more dangerous failure mode.
  </TabItem>
  <TabItem value="m4" label="🚨 4. Confusing TP Rate with Overall Accuracy">
    <br/>
    
    *   **The Misconception:** *"Accuracy measures what percentage of positive events were caught."*
    *   **❌ Wrong Thinking:** Conflating Accuracy with Recall (Sensitivity).
    *   **✅ The Right Principle:** Accuracy divides correct predictions by the total population. Recall divides correct positive hits by the actual positive population ($\frac{\text{TP}}{\text{TP} + \text{FN}}$).
  </TabItem>
  <TabItem value="m5" label="🚨 5. Inverting Class Label Assignments">
    <br/>
    
    *   **The Misconception:** *"Labeling healthy as 1 and sick as 0 changes nothing about metric calculations."*
    *   **❌ Wrong Thinking:** Arbitrarily assigning the positive class ($1$).
    *   **✅ The Right Principle:** In statistical convention, the rare, actionable, or targeted event (fraud, disease, churn, defect) is assigned as the **Positive Class ($1$)**. Inverting labels flips Precision, Recall, and Sensitivity calculations.
  </TabItem>
</Tabs>

<details>
  <summary>❓ <b>1. [THEORY] How are the four quadrants of a confusion matrix mapped in scikit-learn when calling `cm.ravel()`?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   In scikit-learn, binary confusion matrices are ordered by class labels $[0, 1]$:
        *   Row 0: Actual Negatives ($y=0$) $\implies$ Columns $[0, 1]$ are **$\text{TN}, \text{FP}$**.
        *   Row 1: Actual Positives ($y=1$) $\implies$ Columns $[0, 1]$ are **$\text{FN}, \text{TP}$**.
    *   Calling `tn, fp, fn, tp = confusion_matrix(y_true, y_pred).ravel()` unpacks them in exact row-major order:
        $$\text{Index } 0 \to \text{TN}, \quad \text{Index } 1 \to \text{FP}, \quad \text{Index } 2 \to \text{FN}, \quad \text{Index } 3 \to \text{TP}$$
  </div>
</details>

<details>
  <summary>❓ <b>2. [ANALYZE] Why is a Type II error (False Negative) typically considered far more dangerous than a Type I error (False Positive) in medical diagnostics?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Type I Error (False Positive):** A healthy patient is flagged as potentially having disease. The consequence is a follow-up test, temporary anxiety, and slight medical expense.
    *   **Type II Error (False Negative):** A patient with an aggressive tumor is told they are healthy. The consequence is missed treatment, disease progression, and avoidable mortality.
    *   Because the cost of missing a true positive is catastrophic, diagnostic models prioritize high Recall (minimizing $\text{FN}$) over high Precision.
  </div>
</details>

  <summary>❓ <b>3. [MATH] Given TN = 85, FP = 15, FN = 5, TP = 95, calculate Overall Accuracy and Specificity.</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Total Observations:** $N = 85 + 15 + 5 + 95 = 200$.
    *   **Accuracy:**
        $$\text{Accuracy} = \frac{\text{TP} + \text{TN}}{N} = \frac{95 + 85}{200} = \frac{180}{200} = 0.90 \quad (90.0\%)$$
    *   **Specificity (True Negative Rate):**
        $$\text{Specificity} = \frac{\text{TN}}{\text{Actual Negatives}} = \frac{\text{TN}}{\text{TN} + \text{FP}} = \frac{85}{85 + 15} = \frac{85}{100} = 0.85 \quad (85.0\%)$$
  </div>
</details>

<details>
  <summary>❓ <b>4. [PRACTICE] How do you compute the baseline accuracy of a dataset containing 850 non-churners and 150 churners?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Majority Class:** Non-churners with 850 samples.
    *   **Total Samples:** $850 + 150 = 1000$.
    *   **Baseline Zero-Rule Accuracy:**
        $$\text{Baseline} = \frac{850}{1000} = 0.85 \quad (85.0\%)$$
    *   A churn prediction model that achieves $86.0\%$ accuracy provides almost zero value (+1.0% lift over blind guessing).
  </div>
</details>

<details>
  <summary>❓ <b>5. [THEORY] Can accuracy ever be higher than both Precision and Recall simultaneously?</b></summary>
  <div className="answer-content">
    <br/>
    
    *   **Yes:** If a dataset has heavy negative class dominance (e.g. 90% negatives) and the model accurately classifies negatives ($\text{TN}$ is high), while missing some positives ($\text{FN}$ is moderate) and making a few false alarms ($\text{FP}$ is low).
    *   Accuracy will be buoyed by the large $\text{TN}$ count, even if Precision and Recall on the rare positive class are mediocre.
  </div>
</details>
