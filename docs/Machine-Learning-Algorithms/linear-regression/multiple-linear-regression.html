Multiple Linear Regression

Topic — The previous page fitted one feature and found something unresolved: age had a real effect of −800-800−800 that its marginal correlation of −0.0392-0.0392−0.0392 completely hid, and only became visible once size's contribution was removed. Doing that removal automatically, for every feature at once, is what multiple regression is. This page works out how, and then asks which measure can be trusted to tell you whether an added feature helped.

The model, and the meaning of one coefficient​

Each feature gets its own coefficient:

y=b0+b1x1+b2x2+⋯+bkxky = b_0 + b_1 x_1 + b_2 x_2 + \dots + b_k x_ky=b0​+b1​x1​+b2​x2​+⋯+bk​xk​

With one feature this is a line, with two a plane, with more a hyperplane — impossible to picture and no different algebraically.

The definition of bib_ibi​ is the part that carries all the weight:

Holding every other feature in the model constant, one additional unit of xix_ixi​ is associated with a bib_ibi​ increase in yyy.

Both qualifications are load-bearing, and the first one is not a caveat but a description of what the arithmetic actually does. "Holding every other feature constant" means bib_ibi​ is fitted on the variation in xix_ixi​ that the other features cannot explain — exactly the residual-then-refit operation the previous page did by hand. "Is associated with" is not "causes"; regression measures association, and nothing about fitting a hyperplane establishes direction.

Solving for two coefficients by hand​

The two-feature case has a closed form small enough to compute on paper, and doing so shows where the "holding constant" behaviour comes from mechanically.

Working in deviations from the means — d1i=x1i−xˉ1d_{1i} = x_{1i} - \bar{x}_1d1i​=x1i​−xˉ1​, and so on — the least-squares coefficients satisfy two simultaneous equations, the normal equations:

S11⋅b1+S12⋅b2=S1yS_{11} \cdot b_1 + S_{12} \cdot b_2 = S_{1y}S11​⋅b1​+S12​⋅b2​=S1y​

S12⋅b1+S22⋅b2=S2yS_{12} \cdot b_1 + S_{22} \cdot b_2 = S_{2y}S12​⋅b1​+S22​⋅b2​=S2y​

where S11=∑d1i2S22=∑d2i2S12=∑d1id2i\text{where } S_{11} = \sum d_{1i}^2 \qquad S_{22} = \sum d_{2i}^2 \qquad S_{12} = \sum d_{1i}d_{2i}where S11​=∑d1i2​S22​=∑d2i2​S12​=∑d1i​d2i​

S1y=∑d1idyiS2y=∑d2idyiS_{1y} = \sum d_{1i}d_{yi} \qquad S_{2y} = \sum d_{2i}d_{yi}S1y​=∑d1i​dyi​S2y​=∑d2i​dyi​

S11S_{11}S11​ and S22S_{22}S22​ measure how much each feature varies. S12S_{12}S12​ measures how much they vary together — and it is the only term that couples the two equations. Set S12=0S_{12} = 0S12​=0 and they decouple completely: b1=S1y/S11b_1 = S_{1y}/S_{11}b1​=S1y​/S11​ and b2=S2y/S22b_2 = S_{2y}/S_{22}b2​=S2y​/S22​, each identical to its simple-regression value. Everything interesting about multiple regression lives in S12S_{12}S12​.

That determinant is the whole story of collinearity

det = S₁₁S₂₂ − S₁₂² sits in the denominator of both coefficients. S12S_{12}S12​ is the coupling term, so as the two features become more alike, S122S_{12}^2S122​ grows toward S11S22S_{11}S_{22}S11​S22​ and the determinant heads to zero — dividing by something arbitrarily small. This is the algebraic source of every instability later on this page, and at exactly S122=S11S22S_{12}^2 = S_{11}S_{22}S122​=S11​S22​ the determinant is zero and there is no unique solution at all, which is the next page's subject.

The same structure generalises: with kkk features you get kkk simultaneous equations, which is unwieldy by hand and elegant in matrix form — hence the next page.

danger

A coefficient is not a property of a feature

It is a property of a feature in a particular model. Add or drop a correlated column and it changes — 3218.223218.223218.22 to 2921.042921.042921.04 here. Reporting "size is worth 3000 per unit" without stating what else was in the model is not a rounding-level imprecision; it is an incomplete statement.

Marginal correlation is a poor screen​

The obvious way to choose features is to correlate them with the target. On this data that ranking is:

  • corr(size, price)=+0.9849\text{corr(size, price)} = +0.9849corr(size, price)=+0.9849
  • corr(age, price)=−0.0392\text{corr(age, price)} = -0.0392corr(age, price)=−0.0392
  • corr(door_colour, price)=+0.0419\text{corr(door\_colour, price)} = +0.0419corr(door_colour, price)=+0.0419

age, with a real effect of −800-800−800 per year, ranks below door_colour, which is pure noise. Any threshold that keeps door_colour keeps age, and any threshold that drops age drops nothing else of value — the screen simply carries no information about these two.

danger

Training R2R^2R2 never decreases when you add a feature

Not "rarely" — never, as a mathematical fact. The model can always set a new coefficient to zero and do exactly as well as before, so the best achievable fit is at least as good as it was. Twenty columns of noise bought +0.0038+0.0038+0.0038 of training R2R^2R2 and cost −0.0041-0.0041−0.0041 of measured out-of-sample performance.

So training R2R^2R2 cannot be used to decide whether a feature belongs.

The standard answer to that problem is Adjusted R2R^2R2, which penalises the model for the number of features it uses. Look at its column above: 0.97970.97970.9797 for size, age, and 0.9802 for the same model plus twenty columns of pure noise. It ranks the noise model higher.

Why the penalty fails​

Adjusted R2R^2R2 is:

adj R2=1−(1−R2)×n−1n−k−1\text{adj } R^2 = 1 - (1 - R^2) \times \frac{n - 1}{n - k - 1}adj R2=1−(1−R2)×n−k−1n−1​

and the mechanism is a race between two quantities that happen to grow at similar rates. As kkk rises, the penalty factor n−1n−k−1\frac{n-1}{n-k-1}n−k−1n−1​ grows — at k=102,n=120k = 102, n = 120k=102,n=120 it is 119/17=7.0119/17 = 7.0119/17=7.0, a sevenfold inflation of the unexplained variance. But (1−R2)(1 - R^2)(1−R2) is shrinking at almost exactly the rate that offsets it, because spurious columns inflate train R2R^2R2: from 0.97820.97820.9782 to 0.99710.99710.9971, so (1−R2)(1 - R^2)(1−R2) goes 0.0218→0.00290.0218 \to 0.00290.0218→0.0029, a factor of 7.5.

Multiply the two and you get roughly what you started with. The penalty is real, correctly implemented, and almost exactly cancelled by the overfitting it is meant to expose.

danger

Adjusted R² is not an overfitting guard

At n=120n = 120n=120 it failed to flag 100 columns of pure noise. It is a mild correction for the fact that R2R^2R2 cannot decrease — useful for comparing two models that differ by a feature or two, and no substitute for measuring out-of-sample performance.

The number that worked here is cross-validated R2R^2R2, which fell monotonically and by 0.38470.38470.3847. When train R2R^2R2 and CV R2R^2R2 diverge, the training number is the one lying — and Adjusted R2R^2R2 is close enough to a training number to lie with it.

This is also why the honest form of the earlier claim matters: Adjusted R2R^2R2 and cross-validation are often presented as two interchangeable remedies for feature-count inflation. On this data they are not remotely interchangeable. Only one of them worked.

Read the columns carefully, because the result is subtle:

  • The means stay correct. 2.95542.95542.9554 and 3.03733.03733.0373 at the extreme — still centred near 3.003.003.00. Collinearity does not bias the coefficients.
  • The sum stays exact. 5.99285.99285.9928 in the last three rows, against a true total of 6.006.006.00, and it barely moves across the whole table.
  • The spread explodes. Standard deviation of the first coefficient goes 0.0646→1.43120.0646 \to 1.43120.0646→1.4312 — 22× larger — and most of that happens between 0.990.990.99 and 0.9990.9990.999.

The interpretation is precise and worth stating carefully: when two features carry nearly the same information, the data determines their combined effect perfectly well and says almost nothing about how to divide it between them. Any individual fit picks a split more or less arbitrarily, and the next sample picks a different one.

This is multicollinearity. Its consequences:

AffectedHow
PredictionsBarely — the sum is what drives them, and the sum is stable
Individual coefficientsSeverely — unstable, and can even flip sign

Standard errorsInflated, so significance tests fail to reject

What ridge does about it​

Ridge regression adds a penalty on the size of the coefficients, which resolves the ambiguity by preferring the split that keeps them small. At corr=0.999\text{corr} = 0.999corr=0.999:

ModelMean coef1coef_1coef1​Mean coef2coef_2coef2​SD of coef1coef_1coef1​SumTest R2R^2R2
LinearRegression3.26572.73141.83115.99710.9710
Ridge(alpha=1.0)3.02062.95630.23785.97690.9713

The stability gain is dramatic. Coefficient spread drops 1.8311→0.23781.8311 \to 0.23781.8311→0.2378, an 87% reduction, and the split becomes even: the gap between the two means narrows from 0.53420.53420.5342 to 0.06440.06440.0644.

The prediction gain is nil. Test R2R^2R2 goes 0.9710→0.97130.9710 \to 0.97130.9710→0.9713 — an improvement of 0.0003, which is nothing.

That pairing is the lesson, and it confirms the thesis of the table above from the opposite direction: since collinearity was never damaging the predictions, fixing collinearity cannot improve them. What ridge buys is coefficients you can report and reproduce. Whether that is worth a small bias depends entirely on whether anyone is going to read the coefficients.

note

Regularisation gets its own treatment later

Ridge appears here only as the direct answer to collinearity. The penalty term, choosing its strength, and the different behaviour of lasso — which drives coefficients to exactly zero rather than merely shrinking them — belong with generalisation and model control.

3. Common Mistakes​

  • 🚨 1. Absolute Coefficients
  • 🚨 2. Solo Correlation Screening
  • 🚨 3. Trusting Adjusted R²
  • 🚨 4. Collinearity biases fits

  • The Misconception: "A coefficient is an absolute property of a feature."
  • ❌ Wrong Thinking: Believing size is always worth 3000 per unit, regardless of what other columns (like rooms) are included in the fit.
  • ✅ The Right Principle: A coefficient is a property of a feature in a particular model context. Adding or dropping correlated columns immediately shifts other weights (e.g., 3218.22→2921.043218.22 \to 2921.043218.22→2921.04 once rooms joined) as credit is shared.

  • The Misconception: "I should drop features that have near-zero correlation with the target."
  • ❌ Wrong Thinking: Removing age because its solo correlation with house price is −0.0392-0.0392−0.0392.
  • ✅ The Right Principle: Dominant features can completely mask secondary signals. Once dominant features (like size) are controlled for, hidden correlations become extremely clear (e.g., age partial correlation was −0.5758-0.5758−0.5758, significantly boosting CV R2R^2R2).

  • The Misconception: "Adjusted R² is a robust guard against overfitting."
  • ❌ Wrong Thinking: Adding 100 noise columns because Adjusted R2R^2R2 read 0.97940.97940.9794 (higher than the clean 2-feature baseline of 0.97790.97790.9779).
  • ✅ The Right Principle: Adjusted R2R^2R2 is not an overfitting guard. Spurious columns inflate training R2R^2R2 so rapidly that the inflation nearly cancels out the feature-count penalty. Always trust out-of-sample Cross-Validation scoring.

  • The Misconception: "Multicollinearity introduces a bias into our regression coefficients."
  • ❌ Wrong Thinking: Believing collinearity makes the averages of fitted coefficients drift away from the true values.
  • ✅ The Right Principle: Collinearity does not bias coefficients—their means stay exactly correct. Instead, it makes coefficient variance explode, creating massive instability where individual weights swing wildly.

4. Summary​

🤖 Core Theory

  • Normal Equations: Simultaneous equations satisfied by OLS weights. Coupled by the covariance term S12S_{12}S12​.
  • Decoupling Rule: If S12=0S_{12} = 0S12​=0, the equations decouple, and multiple regression collapses into independent simple regressions.
  • Collinearity Root: The determinant S11S22−S122S_{11}S_{22} - S_{12}^2S11​S22​−S122​ sits in the denominator of OLS coefficients. As correlation climbs, determinant heads to zero, blowing up coefficient sizes.
  • Total vs. Direct Effect: Solo fits capture total effects across all channels; joint fits isolate only the direct effect of each feature.

🛠️ Engineering Realities

  • R² Never Decreases: Training R2R^2R2 is mathematically guaranteed to increase or stay constant as columns are added, making it useless for complexity evaluation.
  • Adjusted R² Flatness: Adjusted R2R^2R2 fails completely under heavy noise columns because overfitting and degrees-of-freedom penalties cancel out.
  • Generalization general: Out-of-sample Cross-Validated R2R^2R2 is the only metric that monotonically captures generalization collapse.
  • Ridge regularisation: Ridge adds an L2 size penalty to coefficients, stabilizing their spread (variance) under extreme collinearity without biasing the means.

info

📌 Key Takeaways

  • 🔒 Sum Invariance: Under multicollinearity, while individual coefficients are unstable and change wildly, their combined sum remains perfectly stable and predictions remain robust.
  • ⚖️ Interpretation vs. Prediction: Collinearity completely destroys model interpretation ("how much size adds"), but has almost no effect on prediction performance.
  • 🛠️ Ridge trade-off: Ridge regression does not improve accuracy (test R2R^2R2 stays flat); it buys reportable, stable, and reproducible coefficients.

Review Flashcards​

❓ 1. [THEORY] What does S12=0S_{12} = 0S12​=0 mean, and what happens to the simultaneous normal equations?

  • The Covariance Rule: S12=∑d1id2iS_{12} = \sum d_{1i} d_{2i}S12​=∑d1i​d2i​ measures the covariance (shared variation) between features x1x_1x1​ and x2x_2x2​.
  • If S12=0S_{12} = 0S12​=0, the features are completely orthogonal (uncorrelated).
  • Substituting S12=0S_{12} = 0S12​=0 into the simultaneous normal equations: S11b1+0=S1y  ⟹  b1=S1yS11S_{11} b_1 + 0 = S_{1y} \implies b_1 = \frac{S_{1y}}{S_{11}}S11​b1​+0=S1y​⟹b1​=S11​S1y​​ 0+S22b2=S2y  ⟹  b2=S2yS220 + S_{22} b_2 = S_{2y} \implies b_2 = \frac{S_{2y}}{S_{22}}0+S22​b2​=S2y​⟹b2​=S22​S2y​​
  • The equations decouple completely. Multiple linear regression collapses into two completely independent simple linear regressions, with both slopes equal to their solo values.
❓ 2. [ANALYZE] How does the determinant S11S22−S122S_{11}S_{22} - S_{12}^2S11​S22​−S122​ head to zero, and why does this explode coefficient variance?

  • The Math: Solve the normal equations using Cramer's rule. The determinant sits in the denominator of both coefficients b1b_1b1​ and b2b_2b2​: b1=S1yS22−S12S2yS11S22−S122b_1 = \frac{S_{1y}S_{22} - S_{12}S_{2y}}{S_{11}S_{22} - S_{12}^2}b1​=S11​S22​−S122​S1y​S22​−S12​S2y​​
  • As features become more collinear, their covariance S122S_{12}^2S122​ increases, heading towards the maximum limit S11S22S_{11}S_{22}S11​S22​ (where r=1.0r = 1.0r=1.0).
  • This forces the denominator (determinant) closer and closer to 000. Dividing by an arbitrarily tiny number makes the calculated coefficient value extremely sensitive to minor fluctuations in target measurements (S1y,S2yS_{1y}, S_{2y}S1y​,S2y​), causing coefficient variance to explode.
❓ 3. [THEORY] Why is it mathematically impossible for training R2R^2R2 to decrease when you add a feature?

  • The Optimization Rule: OLS operates by finding coefficients bjb_jbj​ that minimize the Sum of Squared Errors (SSE): Minimize ∑(yi−b0−b1x1i−⋯−bkxki)2\text{Minimize } \sum (y_i - b_0 - b_1 x_{1i} - \dots - b_k x_{ki})^2Minimize ∑(yi​−b0​−b1​x1i​−⋯−bk​xki​)2
  • If you add a new feature xk+1x_{k+1}xk+1​, the optimizer has a new parameter bk+1b_{k+1}bk+1​ to tune.
  • In the worst-case scenario where the new feature is completely useless noise, the optimizer can simply assign bk+1=0b_{k+1} = 0bk+1​=0, achieving the exact same SSE (and thus the exact same R2R^2R2) as before.
  • Because the search space of the optimization has expanded, the minimum SSE can only stay the same or decrease, meaning training R2R^2R2 can never decrease.
❓ 4. [ANALYZE] Why does Adjusted R2R^2R2 completely fail as an overfitting guard against multiple noise columns?

  • The Formula: adj R2=1−(1−R2)×n−1n−k−1\text{adj } R^2 = 1 - (1 - R^2) \times \frac{n-1}{n-k-1}adj R2=1−(1−R2)×n−k−1n−1​.
  • Adding noise columns triggers a literal race between two opposing terms:
    1. As kkk increases, the penalty ratio n−1n−k−1\frac{n-1}{n-k-1}n−k−1n−1​ grows (at k=102,n=120k=102, n=120k=102,n=120, it inflates unexplained variance by 7.0×).
    2. However, because of overfitting, the training unexplained variance (1−R2)(1 - R^2)(1−R2) shrinks from 0.0218→0.00290.0218 \to 0.00290.0218→0.0029 (a 7.5× reduction).
  • The Result: The two factors nearly cancel each other out, making Adjusted R2R^2R2 remain completely flat and completely blind to the fact that the model is fitting pure noise.
❓ 5. [THEORY] How does Ridge regularisation resolve coefficient instability without improving prediction accuracy?

  • Coefficient Stability: Ridge regression adds an L2-norm penalty (α∑bj2\alpha \sum b_j^2α∑bj2​) to the OLS cost function. When features are collinear, infinite splits of the coefficients yield the same prediction. OLS picks a split randomly, but Ridge enforces stability by picking the split that keeps both coefficients small and evenly distributed, cutting standard deviation by over 85%.
  • No Prediction Gain: Because OLS was already finding a stable combined sum, its predictions were already robust. Restricting the coefficients via Ridge does not change this sum—it merely changes the individual allocation, leaving prediction score virtually unchanged (≈+0.0003\approx +0.0003≈+0.0003 gain).
