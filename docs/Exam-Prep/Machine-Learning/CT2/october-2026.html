2. Real-World Scenario: Email Spam Classification​
  • The Problem: Classifying incoming emails as Spam (y=1y = 1y=1) or Ham (y=0y = 0y=0).
  • Candidate Comparison:
    • Gaussian NB: Poor fit because vocabulary features are sparse count tokens, not normally distributed continuous variables.
    • Bernoulli NB: Only tracks whether a keyword (e.g., "lottery", "urgent") appears or not. It cannot differentiate an email containing the word "offer" once from an aggressive spam email repeating "offer" 25 times.
    • Multinomial NB (Selected Winner):
      • Models the exact integer frequency of each token in the document using Bag-of-Words (or TF-IDF).
      • Heavily penalizes repetitive spam keyword stuffing.
      • Scales robustly to large vocabularies (V>50,000V > 50,000V>50,000) via Laplace smoothing: θ^yi=Nyi+αNy+α∣V∣\hat{\theta}_{yi} = \frac{N_{yi} + \alpha}{N_y + \alpha \lvert V \rvert}θ^yi​=Ny​+α∣V∣Nyi​+α​
  • Justification: Multinomial Naïve Bayes is the most suitable variant for full-text document classification because word occurrence frequency directly correlates with semantic intent and spam probability.

Solution 2 (20 Marks)​

1. Concept of Decision Tree Classifier (4 Marks)​

A Decision Tree is a non-parametric supervised learning algorithm that recursively partitions the feature space into axis-aligned rectangular regions using a greedy top-down heuristic (such as ID3 or C4.5).

  • Root & Internal Nodes: Test conditions on specific input attributes.
  • Branches: Outcomes of the test conditions.
  • Leaf Nodes: Terminal class predictions (assigned via majority vote of instances reaching that node).

3. How Decision Trees Handle Overfitting (6 Marks)​

Unconstrained decision trees grow until every leaf node is 100%100\%100% pure, capturing sample-specific noise and outliers (high variance / overfitting). Decision trees mitigate overfitting via two primary mechanisms:

1. Pre-Pruning (Early Stopping Constraints)​

Halts tree growth during construction if specific threshold criteria are violated:

  • max_depth: Limits tree depth to prevent deep, isolated decision paths.
  • min_samples_split: Enforces a minimum number of samples required to consider splitting an internal node (e.g., N≥10N \ge 10N≥10).
  • min_samples_leaf: Mandates that leaf nodes contain at least MMM instances (e.g., M≥5M \ge 5M≥5).
  • min_impurity_decrease: Rejects splits that yield an Information Gain below a threshold ϵ\epsilonϵ.
2. Post-Pruning (Cost-Complexity Pruning / Minimal Error Pruning)​

Allows the tree to grow to full depth, then prunes non-essential subtrees bottom-up using a complexity penalty: Rα(T)=R(T)+α∣T∣R_\alpha(T) = R(T) + \alpha \lvert T \rvertRα​(T)=R(T)+α∣T∣ where R(T)R(T)R(T) is the misclassification error, ∣T∣\lvert T \rvert∣T∣ is the number of terminal leaf nodes, and α≥0\alpha \ge 0α≥0 is the regularization parameter (tuned via cross-validation). If removing a subtree causes an increase in error smaller than α\alphaα, the branch is collapsed into a single leaf.

ii. Random Forest Algorithm and Hyperparameter Importance (10 Marks)​

1. Algorithmic Overview​

Random Forest is a bagging-based ensemble that introduces a second layer of stochasticity—Random Feature Subspacing—to decorrelate individual trees:

Two Layers of Randomness:​
  1. Bootstrap Resampling: Each tree is trained on an independent sample of size NNN drawn with replacement (≈63.2%\approx 63.2\%≈63.2% unique instances, leaving 36.8%36.8\%36.8% Out-of-Bag (OOB) samples for unbiased validation).
  2. Random Feature Subspacing: At every internal node split, only a random subset of m≈pm \approx \sqrt{p}m≈p​ features (out of total ppp) is considered.
Ensemble Variance Equation:​

The variance of an ensemble of BBB trees with pairwise correlation ρ\rhoρ is:

Var⁡(Tˉ)=ρσ2+1−ρBσ2\operatorname{Var}(\bar{T}) = \rho \sigma^2 + \frac{1 - \rho}{B} \sigma^2Var(Tˉ)=ρσ2+B1−ρ​σ2

As B→∞B \to \inftyB→∞, the second term approaches 000, leaving ρσ2\rho \sigma^2ρσ2. Random feature subspacing reduces ρ\rhoρ (tree correlation), driving overall ensemble variance down without inflating bias.

2. Key Hyperparameters and Their Technical Significance​
  1. n_estimators (Number of Trees, BBB):
    • Role: Controls ensemble stability. Unlike boosting or deep nets, increasing BBB in Random Forest never causes overfitting; it monotonically reduces variance until out-of-bag error plateaus (typically B∈[100,500]B \in [100, 500]B∈[100,500]).
  2. max_features (mmm):
    • Role: Size of the random feature subset evaluated at each split.
    • Impact: Smaller mmm reduces tree correlation ρ\rhoρ (lowering variance) but increases individual tree bias. Standard default: m=pm = \sqrt{p}m=p​ for classification and m=p/3m = p/3m=p/3 for regression.
  3. max_depth & min_samples_split:
    • Role: Regulates individual tree growth. Allowing deep trees provides low bias, while the ensemble voting layer eliminates the variance.
  4. bootstrap (Boolean) & oob_score:
    • Role: Enables Out-of-Bag validation, providing a free cross-validation estimate without needing a separate validation holdout split.
