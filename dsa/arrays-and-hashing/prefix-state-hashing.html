Invariant 02: Historical Prefix & Complement Lookups

Brute force algorithms often search backward or forward over a collection, leading to quadratic O(N2)O(N^2)O(N2) execution times. The Prefix & Complement Lookup invariant eliminates nested iterations by turning temporal search into an O(1)O(1)O(1) memory inquiry: Has the complementary state required to satisfy the equation already been seen?

The Core Invariant​

info

The Mathematical Invariant

Given an ongoing cumulative evaluation or sequence function S(i)S(i)S(i) and a required relational condition: f(S(i),S(j))=Target(j<i)f(S(i), S(j)) = \text{Target} \quad (j < i)f(S(i),S(j))=Target(j<i)

We rewrite the condition algebraically to isolate the historical state S(j)S(j)S(j): S(j)=g(S(i),Target)S(j) = g(S(i), \text{Target})S(j)=g(S(i),Target)

Instead of executing a nested scan over all previous indices j∈[0,i−1]j \in [0, i-1]j∈[0,i−1], we maintain a hash table of historical states HHH. At step iii, we perform an O(1)O(1)O(1) lookup for g(S(i),Target)g(S(i), \text{Target})g(S(i),Target).

Why It Works​

  1. One-Way Directional Memory: By accumulating state from left to right, we can answer questions about continuous subarrays or pairs in a single linear pass (O(N)O(N)O(N)).
  2. Subarray Sum Reduction: Any contiguous subarray sum from index j+1j+1j+1 to iii can be expressed as the difference of two prefix sums: ∑k=j+1iA[k]=Prefix[i]−Prefix[j]\sum_{k=j+1}^i A[k] = \text{Prefix}[i] - \text{Prefix}[j]∑k=j+1i​A[k]=Prefix[i]−Prefix[j] If this subarray sum equals KKK, then Prefix[j]=Prefix[i]−K\text{Prefix}[j] = \text{Prefix}[i] - KPrefix[j]=Prefix[i]−K.

Example 1: Two Sum (LeetCode 1)​

Difficulty: Easy (Direct Complement) · Practice on LeetCode

Problem Statement: Given an array of integers nums and an integer target, return indices of the two numbers such that they add up to target. You may assume that each input would have exactly one solution, and you may not use the same element twice. You can return the answer in any order.

Examples​

  • Example 1:
    • Input: nums = [2,7,11,15], target = 9
    • Output: [0,1]
    • Explanation: Because nums[0] + nums[1] == 9, we return [0, 1].
  • Example 2:
    • Input: nums = [3,2,4], target = 6
    • Output: [1,2]
  • Example 3:
    • Input: nums = [3,3], target = 6
    • Output: [0,1]

Constraints​

  • 2≤nums.length≤1042 \le \text{nums.length} \le 10^42≤nums.length≤104
  • −109≤nums[i]≤109-10^9 \le \text{nums}[i] \le 10^9−109≤nums[i]≤109
  • −109≤target≤109-10^9 \le \text{target} \le 10^9−109≤target≤109
  • Only one valid answer exists.

Invariant Application​

Equation: A[i]+A[j]=TargetA[i] + A[j] = \text{Target}A[i]+A[j]=Target. Isolated historical state: A[j]=Target−A[i]A[j] = \text{Target} - A[i]A[j]=Target−A[i]. As we scan index iii, check if the complement has been recorded in the hash map. If so, return (H[Target−A[i]],i)(H[\text{Target} - A[i]], i)(H[Target−A[i]],i). Otherwise, record H[A[i]]=iH[A[i]] = iH[A[i]]=i.

  • TypeScript
  • Python
import java.util.HashMap;
import java.util.Map;

public class Solution {
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> seen = new HashMap<>();
        
        for (int i = 0; i < nums.length; i++) {
            int complement = target - nums[i];
            if (seen.containsKey(complement)) {
                return new int[]{seen.get(complement), i};
            }
            seen.put(nums[i], i);
        }
        
        return new int[]{};
    }
}
function twoSum(nums: number[], target: number): number[] {
    const seen = new Map<number, number>();
    
    for (let i = 0; i < nums.length; i++) {
        const complement = target - nums[i];
        if (seen.has(complement)) {
            return [seen.get(complement)!, i];
        }
        seen.set(nums[i], i);
    }
    
    return [];
}
from typing import List

class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        seen = {}
        for i, num in enumerate(nums):
            complement = target - num
            if complement in seen:
                return [seen[complement], i]
            seen[num] = i
        return []
  • Time Complexity: O(N)O(N)O(N) single iteration over the array.
  • Space Complexity: O(N)O(N)O(N) hash table storage to hold up to NNN seen elements.

Follow-up​

Follow-up Question: Can you solve this problem with O(1)O(1)O(1) auxiliary space if the input array is already sorted in non-decreasing order?

Technical Rationale & Solution:

  1. Transition to Two Pointers: If nums is pre-sorted, we transition from the hash table complement invariant to the Two Pointers invariant.
  2. Opposite-End Convergence: Initialize left = 0 and right = nums.length - 1. Because the array is monotonically non-decreasing:
    • If nums[left] + nums[right] < target, the sum must increase, so increment left++.
    • If nums[left] + nums[right] > target, the sum must decrease, so decrement right--.
    • If equal, return [left, right].
  3. Complexity Trade-off: This maintains O(N)O(N)O(N) runtime while dropping additional space complexity from O(N)O(N)O(N) to strictly O(1)O(1)O(1).

Example 2: Subarray Sum Equals K (LeetCode 560)​

Difficulty: Medium (Prefix Frequency Accumulation) · Practice on LeetCode

Problem Statement: Given an array of integers nums and an integer k, return the total number of subarrays whose sum equals to k. A subarray is a contiguous non-empty sequence of elements within an array.

Examples​

  • Example 1:
    • Input: nums = [1,1,1], k = 2
    • Output: 2
    • Explanation: Subarrays [1,1] at indices 0..1 and 1..2 both sum to 2.
  • Example 2:
    • Input: nums = [1,2,3], k = 3
    • Output: 2
    • Explanation: Subarrays [1,2] (indices 0..1) and [3] (index 2) both sum to 3.

Constraints​

  • 1≤nums.length≤2×1041 \le \text{nums.length} \le 2 \times 10^41≤nums.length≤2×104
  • −1000≤nums[i]≤1000-1000 \le \text{nums}[i] \le 1000−1000≤nums[i]≤1000
  • −107≤k≤107-10^7 \le k \le 10^7−107≤k≤107

Invariant Application​

Let current_sum=∑m=0inums[m]\text{current\_sum} = \sum_{m=0}^i \text{nums}[m]current_sum=∑m=0i​nums[m]. We need to find previous indices jjj such that current_sum−prefix_sum[j]=k\text{current\_sum} - \text{prefix\_sum}[j] = kcurrent_sum−prefix_sum[j]=k, which means prefix_sum[j]=current_sum−k\text{prefix\_sum}[j] = \text{current\_sum} - kprefix_sum[j]=current_sum−k. We store the frequency of each seen prefix sum in a hash table. Initialize the table with {0:1}\{0: 1\}{0:1} to handle subarrays starting at index 0.

  • Java
  • TypeScript
  • Python
import java.util.HashMap;
import java.util.Map;

public class Solution {
    public int subarraySum(int[] nums, int k) {
        int count = 0;
        int currentSum = 0;
        Map<Integer, Integer> prefixCounts = new HashMap<>();
        prefixCounts.put(0, 1); // Base case for subarray starting at index 0
        
        for (int num : nums) {
            currentSum += num;
            int neededPrefix = currentSum - k;
            
            count += prefixCounts.getOrDefault(neededPrefix, 0);
            prefixCounts.put(currentSum, prefixCounts.getOrDefault(currentSum, 0) + 1);
        }
        
        return count;
    }
}
function subarraySum(nums: number[], k: number): number {
    let count = 0;
    let currentSum = 0;
    const prefixCounts = new Map<number, number>();
    prefixCounts.set(0, 1);
    
    for (const num of nums) {
        currentSum += num;
        const neededPrefix = currentSum - k;
        
        count += prefixCounts.get(neededPrefix) || 0;
        prefixCounts.set(currentSum, (prefixCounts.get(currentSum) || 0) + 1);
    }
    
    return count;
}

class Solution:
    def subarraySum(self, nums: List[int], k: int) -> int:

        current_sum = 0
        prefix_counts = defaultdict(int)
        prefix_counts[0] = 1 # Base case
        
        for num in nums:
            current_sum += num
            needed_prefix = current_sum - k

            prefix_counts[current_sum] += 1
            
        return count
  • Time Complexity: O(N)O(N)O(N) linear pass.
  • Space Complexity: O(N)O(N)O(N) space for the hash map of unique prefix sums.

Follow-up​

Follow-up Question: Why does the sliding window (two pointers) approach fail on this problem? Under what exact constraint change would sliding window become viable?

Technical Rationale & Solution:

  1. Monotonicity Breakdown: The sliding window technique requires monotonicity: expanding the right pointer must strictly non-decrease the window sum, and advancing the left pointer must strictly non-increase it.
  2. Negative Values Invalidate Pointers: Because nums[i] can be negative (e.g., nums = [1, -1, 1, -1], k = 0), expanding the right pointer could cause the sum to decrease, and shrinking the left pointer could cause the sum to increase. There is no deterministic decision rule for pointer movement.
  3. Constraint for Sliding Window: A sliding window is only viable if the problem statement guarantees all non-negative integers (∀i,nums[i]≥0\forall i, \text{nums}[i] \ge 0∀i,nums[i]≥0). When negative numbers are present, prefix sum hashing is mandatory.

Example 3: Contiguous Array (LeetCode 525)​

Difficulty: Medium (Parity Balancing / State Normalization) · Practice on LeetCode

Problem Statement: Given a binary array nums, return the maximum length of a contiguous subarray with an equal number of 0 and 1.

Examples​

  • Example 1:
    • Input: nums = [0,1]
    • Output: 2
    • Explanation: [0, 1] is the longest contiguous subarray with an equal number of 0 and 1.
  • Example 2:
    • Input: nums = [0,1,0]
    • Output: 2
    • Explanation: [0, 1] (or [1, 0]) is a longest contiguous subarray with equal 0s and 1s.

Constraints​

  • 1≤nums.length≤1051 \le \text{nums.length} \le 10^51≤nums.length≤105
  • nums[i] is either 0 or 1.

Invariant Application​

Transform the problem domain: replace each 0 with -1. Now, an equal number of 0s and 1s translates to a contiguous subarray sum of zero: Prefix[i]−Prefix[j]=0  ⟺  Prefix[i]=Prefix[j]\text{Prefix}[i] - \text{Prefix}[j] = 0 \iff \text{Prefix}[i] = \text{Prefix}[j]Prefix[i]−Prefix[j]=0⟺Prefix[i]=Prefix[j] We store the first index at which each prefix sum was seen. To maximize length (i−j)(i - j)(i−j), we keep early indices and never overwrite existing map entries.

  • Java
  • TypeScript
  • Python
import java.util.HashMap;
import java.util.Map;

public class Solution {
    public int findMaxLength(int[] nums) {
        Map<Integer, Integer> firstSeen = new HashMap<>();
        firstSeen.put(0, -1); // Prefix sum 0 before the array starts
        
        int maxLength = 0;
        int runningSum = 0;
        
        for (int i = 0; i < nums.length; i++) {
            runningSum += (nums[i] == 1) ? 1 : -1;
            
            if (firstSeen.containsKey(runningSum)) {
                maxLength = Math.max(maxLength, i - firstSeen.get(runningSum));
            } else {
                firstSeen.put(runningSum, i);
            }
        }
        
        return maxLength;
    }
}
function findMaxLength(nums: number[]): number {
    const firstSeen = new Map<number, number>();
    firstSeen.set(0, -1);
    
    let maxLength = 0;
    let runningSum = 0;
    
    for (let i = 0; i < nums.length; i++) {
        runningSum += nums[i] === 1 ? 1 : -1;
        
        if (firstSeen.has(runningSum)) {
            maxLength = Math.max(maxLength, i - firstSeen.get(runningSum)!);
        } else {
            firstSeen.set(runningSum, i);
        }
    }
    
    return maxLength;
}
from typing import List

class Solution:
    def findMaxLength(self, nums: List[int]) -> int:
        first_seen = {0: -1}
        max_length = 0
        running_sum = 0
        
        for i, num in enumerate(nums):
            running_sum += 1 if num == 1 else -1
            
            if running_sum in first_seen:
                max_length = max(max_length, i - first_seen[running_sum])
            else:
                first_seen[running_sum] = i
                
        return max_length
  • Time Complexity: O(N)O(N)O(N) single pass over the array.
  • Space Complexity: O(N)O(N)O(N) hash table storage for prefix sum states.

Follow-up​

Follow-up Question: How does this invariant generalize if the array contains three distinct values (e.g., 0, 1, and 2) and we want the longest contiguous subarray with an equal number of all three elements?

Technical Rationale & Solution:

  1. Multi-Dimensional State Balance: For two values, balance is a single scalar: Δ=count(1)−count(0)\Delta = \text{count}(1) - \text{count}(0)Δ=count(1)−count(0). For three values, balance requires two simultaneous invariant equations: Δ10=count(1)−count(0)\Delta_{10} = \text{count}(1) - \text{count}(0)Δ10​=count(1)−count(0) Δ20=count(2)−count(0)\Delta_{20} = \text{count}(2) - \text{count}(0)Δ20​=count(2)−count(0)
  2. State Tuple Hashing: Maintain running counters for 0, 1, and 2. At each index iii, construct the composite state tuple (Δ10,Δ20)(\Delta_{10}, \Delta_{20})(Δ10​,Δ20​).
  3. Earliest Occurrence Invariant: Store the earliest index for each tuple in a hash map. If (Δ10,Δ20)(\Delta_{10}, \Delta_{20})(Δ10​,Δ20​) reappears at index jjj, all three counts grew by the identical amount over (first_seen,j](first\_seen, j](first_seen,j], yielding O(N)O(N)O(N) runtime.

Example 4: Subarray Sums Divisible by K (LeetCode 974)​

Difficulty: Medium / Hard (Modulo Congruence Invariant) · Practice on LeetCode

Problem Statement: Given an integer array nums and an integer k, return the number of non-empty subarrays that have a sum divisible by k. A subarray is a contiguous part of an array.

Examples​

  • Example 1:
    • Input: nums = [4,5,0,-2,-3,1], k = 5
    • Output: 7
    • Explanation: There are 7 subarrays with a sum divisible by k = 5: [4, 5, 0, -2, -3, 1], [5], [5, 0], [5, 0, -2, -3], [0], [0, -2, -3], [-2, -3].
  • Example 2:
    • Input: nums = [5], k = 9
    • Output: 0

Constraints​

  • 1≤nums.length≤3×1041 \le \text{nums.length} \le 3 \times 10^41≤nums.length≤3×104
  • −104≤nums[i]≤104-10^4 \le \text{nums}[i] \le 10^4−104≤nums[i]≤104
  • 2≤k≤1042 \le k \le 10^42≤k≤104

Invariant Application​

Two prefix sums have a difference divisible by KKK if and only if they share the same remainder when divided by KKK: (Prefix[i]−Prefix[j])(modK)=0  ⟺  Prefix[i](modK)≡Prefix[j](modK)(\text{Prefix}[i] - \text{Prefix}[j]) \pmod K = 0 \iff \text{Prefix}[i] \pmod K \equiv \text{Prefix}[j] \pmod K(Prefix[i]−Prefix[j])(modK)=0⟺Prefix[i](modK)≡Prefix[j](modK) Because Python handles negative modulo natively while Java and TypeScript yield negative results for negative dividends, we normalize remainder calculations via ((sum % k) + k) % k.

  • Java
  • TypeScript
  • Python
import java.util.HashMap;
import java.util.Map;

public class Solution {
    public int subarraysDivByK(int[] nums, int k) {
        Map<Integer, Integer> remainderCounts = new HashMap<>();
        remainderCounts.put(0, 1);
        
        int count = 0;
        int runningSum = 0;
        
        for (int num : nums) {
            runningSum += num;
            // Normalize negative remainders
            int remainder = ((runningSum % k) + k) % k;
            
            count += remainderCounts.getOrDefault(remainder, 0);
            remainderCounts.put(remainder, remainderCounts.getOrDefault(remainder, 0) + 1);
        }
        
        return count;
    }
}

Follow-up​

Follow-up Question: Since k≤104k \le 10^4k≤104, how can we optimize memory footprint, GC pressure, and cache locality compared to a dynamic hash table?

Technical Rationale & Solution:

  1. Direct Array Indexing: Because the normalized remainder is strictly bounded in the discrete range [0,k−1][0, k-1][0,k−1], we can eliminate dynamic heap-allocated hash map nodes by allocating a primitive array int[] remainderCounts = new int[k].
  2. Hardware Benefits:
    • Eliminates object boxing/unboxing (Integer vs int).
    • Guarantees O(1)O(1)O(1) lookup and increment with zero hash collisions or bucket chaining.
    • Provides sequential memory layout with L1/L2L1/L2L1/L2 CPU cache locality.
    • Reduces space from O(N)O(N)O(N) dynamic map overhead to fixed O(k)O(k)O(k) memory.
